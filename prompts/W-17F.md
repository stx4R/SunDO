## 1. 🔴 보정 ① — 행 우측 끝이 서로 어긋난다

### 1.1 관측 (실기기 · Dev 창)

`.set-*`이 `@layer`로 옮겨져 행 구조는 살아났다. 그런데 **우측 요소의 x가 행마다 다르다.**

| 행 | 우측 요소 | 관측 |
| --- | --- | --- |
| 알림 카드 | 토글 | 카드 우측 끝에 붙는다 ✅ **이것이 기준이다** |
| 앱 · `버전` | `0.10.0` 값 | 토글과 **같은 끝** ✅ |
| 앱 · `홈 화면에 추가` | `설치 안내` 칩 | 🔴 **안쪽으로 들어와 있다** |
| 앱 · `데이터 새로고침` | `›` | 🔴 안쪽 |
| 약관·정책 3행 | `›` | 🔴 안쪽 |

⚠ **구분선(border-bottom)의 좌우 끝도 행마다 다르다.** 같은 원인일 가능성이 높다.

### 1.2 🔴 원인을 진단하고 고쳐라 — 추측으로 여백을 더하지 마라

`0.10.0`이 붙는 행과 칩·`›`가 붙는 행의 **차이가 무엇인지**부터 찾아라.

| 확인 | 어떻게 |
| --- | --- |
| 두 행의 **태그가 다른가** | `버전`은 `div`이고 칩·`›` 행은 `button`인가 |
| 🔴 **버튼 UA 기본값** | `button`은 브라우저 기본 `padding`·`border`·`font`·`text-align`을 갖는다. `.set-row`가 그것을 초기화하는가 |
| **폭** | 버튼이 `width:100%` · `box-sizing:border-box`인가. 아니면 내용만큼만 넓어 `space-between`이 벌릴 공간이 없다 |
| **감싸는 요소** | 칩·`›`가 별도 wrapper 안에 있고 그 wrapper가 여백을 갖는가 |

🔴 **DevTools로 실측하라** — 두 행의 `getBoundingClientRect().right`와 `padding`·`width`·
`box-sizing`을 나란히 찍어 비교한다. 값이 어디서 갈리는지 보고 그 지점만 고쳐라.

**고치는 방향** — design `20a`는 **모든 행이 같은 형태**다:

```
height:52px; display:flex; align-items:center; justify-content:space-between;
gap:12px; border-bottom:1px solid rgba(20,53,38,0.06)
```

행이 `button`이어야 한다면 UA 기본값을 **전부 초기화**하고 위 형태를 그대로 얹어라
(`width:100%` · `padding:0` · `border:0` · `background:none` · `font:inherit` ·
`text-align:left` · `box-sizing:border-box` · `color:inherit`).

⚠ **`padding-right`나 `margin-right`를 더해서 눈으로 맞추지 마라.** 그것은 원인을 덮는 것이고,
루트 32px(AC-05)이나 200% 확대에서 다시 어긋난다.

### 1.3 검증 — 🔴 computed로 증명한다

| # | 조건 |
| --- | --- |
| 1 | 🔴 알림 토글 · `0.10.0` · `설치 안내` 칩 · `›` **4종의 우측 x가 모두 같다** |
| 2 | 🔴 모든 행의 `border-bottom` **좌우 끝이 같다** |
| 3 | 모든 행이 `display:flex` · `justify-content:space-between` · `box-sizing:border-box` |
| 4 | 카드 내 마지막 행에는 `border-bottom`이 **없다**(design `20a` 그대로) |
| 5 | reduce · 루트 32px · 200% 확대에서 가로 스크롤 **0** |

`reports/W-17.md` §3.1의 「⬜ 실기기 육안 확인」 칸을 이 실측으로 채워라.

## 2. 🔴 보정 ② — `htm0303` 재가입이 코드 입력에서 막힌다

### 2.1 관측

되살린 `25_htm0303@dshs.kr`로 **가입 신청(S2)에 도달했고**, 코드를 입력해도 진행되지 않는다.
코드를 재발급해도 같다.

### 2.2 🔴 증상이 아니라 **첫 번째 이상**을 먼저 물어라

**`htm0303`은 지금 `status: 'active'`다**(§5.2에서 네가 되돌렸다).
🔴 **active 계정은 S2에 갈 이유가 없다.** 홈으로 가야 한다.

→ **「코드가 안 먹는다」보다 「왜 S2로 갔는가」가 먼저다.** 코드 실패는 그 결과일 수 있다.
예를 들어 S2의 가입 신청은 `users` **create**인데, 문서가 **이미 존재하면** create는 실패한다.

### 2.3 진단 순서 — 🔴 데이터부터 읽고, 그다음 사용자에게 문구를 물어라

**① Admin SDK로 읽어라**(읽기 전용)

| 대상 | 확인 |
| --- | --- |
| `users/{oNRfg2}` | `status` · `role` · `withdrawnAt` 부재 · 전체 키 수 |
| `approvalRequests` | 🔴 `uid == oNRfg2`인 문서가 **남아 있는가** · 그 `status` |
| `inviteCodes` | 활성 코드 1건인가 · `isActive` · `expiresAt` · `useCount` / `maxUses` |
| `departments` | `activeInviteCodeId`가 그 활성 코드를 가리키는가 |

**② 사용자에게 물어라 — 🔴 화면에 뜬 문구를 그대로**

문구가 원인을 가른다. 추측하지 말고 받아라.

| 문구 | 가리키는 것 |
| --- | --- |
| `존재하지 않는 코드입니다` | `lookupInviteCode`가 문서를 못 찾았다 — 코드 문자열 또는 문서 ID |
| `네트워크에 연결할 수 없습니다` | 🔴 **`inviteCodes` 단건 `get`이 규칙에 막혔다** |
| `이미 신청이 접수되었습니다` 계열 | `approvalRequests` 잔존 문서 |
| 아무 반응 없음 | `users` create 실패(문서가 이미 있다) — 콘솔에 `permission-denied`가 찍힌다 |

**③ DevTools 콘솔** — `Missing or insufficient permissions`가 어느 경로에서 나는지.
🔴 **어느 컬렉션의 어느 연산인지**까지 받아라.

### 2.4 🔴 원인이 갈리는 지점에서 판단하라

| 원인 | 성격 | 처리 |
| --- | --- | --- |
| **active 계정인데 앱이 S2로 보냈다** | 🔴 **앱 버그**(라우팅·프로필 판정) | W-17 범위 밖이다. §3으로 물어라 |
| **브라우저가 옛 세션·캐시를 물었다** | 측정 문제 | 시크릿 전부 닫고 재시도. 재현 안 되면 그렇게 기록 |
| **`users` create가 기존 문서에 막혔다** | 🔴 **정상 동작이다** | active 계정은 재가입할 수 없는 것이 맞다. 다만 화면이 그 이유를 말하지 않는다면 §8.10 규격 공백이다 |
| **`inviteCodes` 단건 `get`이 막혔다** | 🔴 **심각하다** | 신입 부원이 아무도 못 들어온다. 즉시 §3으로 보고. **규칙을 넓히지 마라** |
| **`approvalRequests` 잔존 문서** | 데이터 상태 | 콘솔에서 정리 절차를 `database_ToDo/W-17.md`에 적어라 |

⚠ **`htm0303`은 콘솔로 되살린 시험 계정이다.** 「active인 계정이 재가입을 시도한다」는
**실사용에 없는 경로**일 수 있다. 그렇다면 결론은 「버그 아님」이고, 그 판정 근거를 남기면 된다.
🔴 **다만 그렇게 결론 내리기 전에 §2.3의 데이터를 전부 읽어라.**

### 2.5 진짜 확인해야 하는 것 — **미가입 계정의 가입 경로**

`htm0303`이 무엇이든, W-16D 5-3에서 실물로 통과한 그 경로가 **지금도 살아 있는지**가 핵심이다.
🔴 규칙 배포 이후 `inviteCodes` 단건 `get`이 막히면 **신입 부원이 아무도 가입할 수 없다**
(W-16.md §4 위험 3순위).

→ 판단이 「버그 아님」으로 나더라도, **미가입 `@dshs.kr` 계정 1개로 가입 신청이 되는지**를
확인할 필요가 있는지 §3으로 물어라. 계정 확보는 사용자 몫이다.
