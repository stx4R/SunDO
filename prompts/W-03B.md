## §1 `Field` 수정 1건 — `ref.validate()`는 성공을 켜지 않는다

`runValidate(value, true)` → `runValidate(value)`로 바꾼다.

**근거**: `ref.validate()`는 제출 순간에 호출된다. 전부 통과하면 화면이 즉시 넘어가므로
0.28초짜리 체크 드로잉을 볼 이유가 없고, 일부 실패하면 **실패한 필드에 주의를 모아야 하는데**
통과 필드에 초록 체크가 동시에 뜨면 시선이 갈라진다. 제출 시점의 주인공은 에러다.

**주의 — 켜지 않는 것이지 끄는 것이 아니다.** blur로 이미 성공 상태가 된 필드는
`ref.validate()`를 거쳐도 성공 표시를 유지해야 한다. `allowSuccess: false`가
기존 `ok` 상태를 `false`로 되돌리지 않는지 확인하라.

**스토리 페이지에서 상태 4를 만드는 방법**: 마운트 직후 해당 필드에 `focus()` → `blur()`를
1회 실행한다. 실제 사용자 경로와 같으므로 우회가 아니다.

`@theme`에 아래 1개만 추가하고 `.ff-ro` 배경이 이를 참조하게 한다.

## §3 토큰화 기준 — 앞으로 이 기준을 쓴다

> **서로 다른 컴포넌트 2개 이상에서 쓰이면 토큰. 같은 컴포넌트의 상태 변형에서 반복되는 것은 토큰이 아니다.**

`inset 0 1px 3px rgba(20,53,38,0.05)`가 `.ff` 계열에서 5회 반복되는 것은 `box-shadow`가
단일 속성이라 각 상태가 전체 스택을 다시 적어야 하는 **CSS 기계적 중복**이지 토큰 수요가 아니다.
`@theme`과 `cn.ts` 양쪽에 유지 링크만 늘어난다.

다만 이 값은 **S6 사유 세그먼트 컨테이너에도 쓰인다**(Claude Design R-07:
`배경 rgba(255,255,255,0.6), 테두리 1px rgba(255,255,255,0.85), inset 0 1px 3px rgba(20,53,38,0.05)`).
컴포넌트 2개가 되는 시점이므로 **W-09에서 `--shadow-inset-soft`로 승격한다.** 이번에는 두지 마라.

### 6.4 `Chip` / `FilterChip` — 2개로 나눈다

부록 C는 `Chip` 하나로 적었으나 `.chip`(정적 표시)과 `.fchip`(필터 선택)은 역할이 다르다.
하나에 `variant`로 몰면 호출부에서 어느 쪽인지 읽히지 않는다. **2개로 만들고 보고서에 적는다.**

```ts
interface ChipProps { children: ReactNode; className?: string; }          // .chip
interface FilterChipProps {                                               // .fchip / .fchip-on
  label: string;
  active: boolean;
  onClick: () => void;
}
```
- `Chip` 사용처: 인원 수, 상태 표시, 역할 배지
- `FilterChip` 사용처: S7 필터 4개(`전체`·`복장 불량`·`실내화 미착용`·`기타`)
- 필터 4개가 `gap 6`으로 **한 줄에 들어가야 하고 가로 스크롤을 만들면 안 된다**(§8.7.3).
  스토리 페이지에서 430px 폭으로 확인하라.
- 활성 칩은 배경 반전 + `font-weight: 700` **둘 다** 건다(AC-04 — 색만으로 상태를 전달하지 않는다).

### 6.5 `Pill`

```ts
interface PillProps {
  children: ReactNode;
  variant: 'soft' | 'fill' | 'line';
  onClick?: () => void;
}
```
- `.pill` + `.pill-{variant}`. 사용처: 승인·거절·양도.
- 눌림 `scale`은 §7.4가 `0.92~0.95` 범위로만 적었다. **design에서 이식하고, 없으면 `0.95`로

  이번에 실제 목록 행에 렌더한 뒤 어색하면 §9에 적어라. **임의로 그림자를 넣지 마라.**

### 7.3 탭 5개 — 순서 고정

| 순서 | 라벨 | 아이콘 | 표시 조건 |
| --- | --- | --- | --- |
| 1 | 홈 | 집 | 전 역할 |
| 2 | 기록 | 문서(직사각형 + 가로줄 2개) | 전 역할 |
| 3 | 일정 | 달력 | 전 역할 |
| 4 | 관리 | 방패 | `member`는 **항목 자체를 렌더링하지 않는다** |
| 5 | 설정 | 톱니(원 + 8개 톱니, stroke 1.9, 가운데 원 지름 6) | 전 역할 |

- `member`는 4탭이 되고 `space-around`로 균등 재배치된다.
- 5탭에서 항목 사이 간격이 `8px` 미만이면 **항목 폭을 54까지만** 줄이고,
  그래도 부족하면 아이콘을 `19px`로 줄인다. **라벨 텍스트는 어떤 경우에도 축약하지 않는다.**

### 7.4 모션

- 활성 알약이 이전 탭에서 새 탭으로 `0.24s cubic-bezier(.2,.8,.25,1)` **가로 슬라이드**
- 새 탭 아이콘 `scale(0.9) → 1` `0.18s`
- 라벨 색 `0.15s` 크로스페이드
- 알약은 절대 위치 요소 1개를 이동시킨다. 항목마다 배경을 켜고 끄면 슬라이드가 안 된다.
- **프로토타입의 `mousemove` 기반 독 확대(맥OS Dock 효과)는 구현하지 않는다**(§6.2 명시).

### 7.5 API — 라우터에 의존하지 않는다

```ts
type DockTab = 'home' | 'records' | 'duty' | 'admin' | 'settings';

interface DockProps {
  active: DockTab;
  onChange: (tab: DockTab) => void;
  role: 'member' | 'vice' | 'head' | 'teacher' | 'dev';
}
```

- 라우트 이동은 W-05가 `onChange`에 연결한다. Dock 안에서 `navigate`를 부르지 마라.
- **여백을 만들지 마라.** `AppShell`이 `hasDock`으로 이미 소유한다.
- 접근성: `role="tablist"` + 각 항목 `role="tab"` + `aria-selected`. 아이콘은 `aria-hidden`.

### 7.6 아이콘

`src/components/icons.tsx`에 인라인 SVG로 5종을 둔다.

## §8 `Footer` — `src/components/Footer.tsx`

PRD **§6.4 Footer 상세(C6)** + Claude Design **R-06**. 채택 산출물 `14a`~`14c`.

### 8.1 공통

좌우 패딩 `22px`. 상단 구분선 `1px --color-sundo-divider`, 구분선 아래 `padding-top: 22px`.
**배경을 깔지 않는다**(스테이지 그라디언트가 비친다). 링크는 밑줄 없이 `--color-sundo-700`.

**모든 링크는 시각 높이를 유지한 채 투명 패딩으로 세로 44px를 확보한다**(C6 명시).
다른 컴포넌트의 44px 보정은 W-18이지만 Footer는 규격에 박혀 있으므로 이번에 한다.

### 8.2 변형 A — 전체형 (S10)

1. **로고 줄** — 좌측 원형 `32px` 로고(흰 배경, 그림자 `0 6px 14px rgba(31,81,56,0.16)`).
   우측 `10px`에 2줄: `SunDO` `text-button`/700 `--color-sundo-800` 자간 `-0.01em` /
   (2px 간격) `자율생활부 · 대전대신고등학교` `text-micro`/500 `--color-sundo-ink-70`
2. `16px` 아래 **정책 링크 줄** — 가로 나열, 링크 사이 세로 구분선(폭 1, 높이 10,
   `rgba(20,53,38,0.18)`), 좌우 `gap 10`. 각 링크 `text-label`/700 `--color-sundo-700`.
   `개인정보 처리방침` · `서비스 이용약관` · `오픈소스 라이선스`
   **폭이 부족하면 2줄로 접되 좌측 정렬 유지, 줄 간격 10px.**
3. `16px` 아래 **저작권 줄** — `© 2026 SunDO. All rights reserved.`
   `text-micro`/500 `--color-sundo-ink-70`, `tabular-nums`
4. `6px` 아래 **개발자 줄** — `Developed by ` `text-micro`/500 `--color-sundo-ink-70` +
   `stx4R` `text-micro`/700 `--color-sundo-700` + 우측 `3px`에 외부 링크 아이콘 `10px`
   `rgba(20,53,38,0.45)`. 링크 `https://stx4r.me/`, `target="_blank" rel="noopener noreferrer"`
5. 하단 여백 `calc(env(safe-area-inset-bottom) + 26px)`.
   **독 여백 120px을 여기에 더하지 마라.** `AppShell`이 이미 갖고 있다.

### 8.3 변형 B — 축약형 (S1 · S2-1)

로고 줄과 상단 구분선을 생략하고 `padding-top: 18px`. 정책 링크는
`개인정보 처리방침` · `서비스 이용약관` **2개만**.

### 8.4 고정 문자열 — 한 글자도 바꾸지 마라

`SunDO` / `© 2026 SunDO. All rights reserved.` / `Developed by stx4R`
번역·축약·연도 변경 금지. 연도는 `2026` 고정이며 `new Date()`로 만들지 마라.

### 8.5 로고 자산

저장소에 학교 로고 이미지가 없으면 **PRD §8.1.2의 폴백 규격**(`자` 이니셜 원형)으로 렌더하고
`logoSrc` prop을 열어둔다. 임의의 이미지를 만들거나 외부에서 받아오지 마라.

### 8.6 API

```ts
interface FooterProps {
  variant: 'full' | 'compact';
  logoSrc?: string;
  onNavigate?: (path: string) => void;   // 없으면 <a href>로 폴백
}
```
정책 링크는 W-05에서 라우터 링크로 교체된다. 지금은 `<a href="/policy/...">`로 둔다.
