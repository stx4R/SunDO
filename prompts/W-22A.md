## 2. 🔴 배포 전 관문 — W-21C ① 사고 방어

**배포 명령을 치기 전에 이것을 먼저 한다. 예외 없다.**

### 2.1 배포할 파일이 이번 변경을 담고 있는가 — 문자열로 확인한다

```bash
git status --porcelain                      # 비어 있어야 한다
git diff --numstat firestore.rules          # 0줄이 정상 (이미 커밋됐다)
git show HEAD:firestore.rules > /tmp/head.rules && diff firestore.rules /tmp/head.rules
```

그 다음 🔴 **세 문자열이 전부 있어야 한다.** 하나라도 없으면 **배포하지 마라.**

| # | 찾을 것 | 어느 회차 것인가 | 없으면 |
| --- | --- | --- | --- |
| 1 | `editsDutyOnly` (또는 `assignmentsByMeal`) | **W-21C** — 순찰 일정 편집 | W-21C 규칙이 사라졌다 |
| 2 | `hasOnly(['useCount'])` | **W-21B** — 부장의 승인 배치가 사는 자리 | 🔴 **배포하면 가입 승인이 죽는다** |
| 3 | `activeInviteCodeId` 가 들어간 `hasOnly` | **W-21B** — `departments` 필드 분할 | W-21B 규칙이 사라졌다 |

```bash
grep -n "editsDutyOnly\|assignmentsByMeal" firestore.rules
grep -n "hasOnly(\['useCount'\])" firestore.rules
grep -n "activeInviteCodeId" firestore.rules
```

⚠ 🔴 **이 확인의 요점은 「테스트를 믿지 않는 것」이다.** W-21C의 사고에서 테스트는
파일이 사라진 **뒤에** 돌아서 잡았다. 여기서는 **배포가 읽을 바로 그 파일**을 본다.

### 2.2 규칙 테스트를 한 번 더 돌린다

```bash
npm run test:rules        # 🔴 231/231 이어야 한다
git diff --numstat firestore.rules   # 🔴 테스트 직후 다시 — 0줄이어야 한다
```

⚠ 🔴 **두 번째 `git diff`가 이 회차의 발명이다.** 하네스가 파일을 덮어쓰고 `finally`에서
되돌리므로, **되돌리기가 실패했는지는 테스트가 끝난 뒤에만 보인다.**
