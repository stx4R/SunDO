### 0.2 확인 요청 3·5번 근거

- **3번(320px)** — PRD 기준 해상도는 430px이고 현행 최소 유통 기기는 375px(iPhone SE 3)이다.
  360px을 하한으로 잡으면 안드로이드까지 덮는다. 320px 하나를 위해 규격 사다리를 늘리면
  흔한 폭에서의 항목 폭이 흔들린다. **최소 지원 폭 360px**을 PRD v1.3에 명시한다.
  320px에서 간격이 0이 되는 것은 지원 범위 밖 동작으로 둔다. **코드를 고치지 마라.**
- **5번(Footer 여백)** — `14a`의 `45px`은 프로토타입이 `env()`를 못 써서 굳힌 값이다.
  실제 iPhone에서는 `safe-area 34px + 26px = 60px`이라 오히려 design보다 여유가 크다.
  짧아 보이는 건 `safe-area: 0`인 데스크톱 브라우저뿐이고 그건 타깃 환경이 아니다.
  **공식(`safe-area + 26px`)이 맞다. 고치지 마라.**

### 0.3 W-03B에서 넘어온 상태

- `AppShell`이 여백을 단독 소유한다. **오버레이도 자체 하단 여백을 만들지 마라.**
- `-webkit-` 접두사를 손으로 적지 마라. lightningcss가 표준 선언을 지운다.
  **이번 작업은 `backdrop-filter`를 3곳(시트·모달·토스트)에서 쓴다. 전부 표준만 적어라.**
- 인라인 `style`로 준 값은 미디어 쿼리가 이길 수 없다. reduce에서 덮을 값은 커스텀 속성으로 넘겨라.
- `spin` 키프레임은 `.ff-spin`·`.btnp-spin`이 공유한다. 재사용하라.
- 스토리 페이지는 화면이 아니라 DoD 실측 대상이다. **W-03A·W-03B 항목을 지우지 말고 이어 붙인다.**
- 라우터 없음. 이번 컴포넌트도 라우터에 의존하지 않는다.

## §1 빌드 스크립트 수정 — 가장 먼저

`package.json`의 `build`를 아래로 바꾼다. **의존성을 추가하지 마라.**

```json
"build": "node -e \"require('fs').rmSync('dist',{recursive:true,force:true})\" && tsc -b && vite build"
```

- `rimraf` 대신 `node -e`를 쓰는 이유: 새 의존성이 없고 Windows `cmd.exe`에서도 동작한다.
  `rm -rf`는 `npm run`이 `cmd.exe`로 실행될 때 깨진다.
- **이건 편의 개선이 아니라 정확성 문제다.** W-03B 재개 세션이 옛 번들을 한동안 실측했다.
  같은 일이 반복되면 통과했다는 DoD가 거짓이 된다.
- `vite.config.ts`는 여전히 건드리지 마라. 저장소를 OneDrive 밖으로 옮기는 건 PM이 별도로 판단한다.

## §2 토큰 2개 승격 + 독 reduce 처리

### 2.1 토큰 2개 — §3 기준(서로 다른 컴포넌트 2개 이상)이 충족됐다

`@theme`에 추가하고 기존 리터럴을 치환한다.

| 값 | 변수명 | 현재 사용처 |
| --- | --- | --- |
| `rgba(20,53,38,0.45)` | `--color-sundo-ink-45` | `Field` 라벨 기본색·자물쇠 / `Dock` 비활성 아이콘 / `Footer` 외부 링크 아이콘 — **3개 컴포넌트** |
| `inset 0 1px 0 rgba(255,255,255,0.85)` | `--highlight-top` | `.glass` / `.dock` — **2개 컴포넌트**. 이번에 시트·모달이 3번째가 된다 |

- `--color-sundo-ink-45`는 `--color-*` 네임스페이스다. `cn.ts` 변경 불필요(색 그룹은 이미 동작).
- `--highlight-top`은 `box-shadow` 스택 안에서 `var()`로만 쓰이므로 **Tailwind 네임스페이스를
  쓰지 않는다**(`--gradient-*`와 같은 처리). 유틸리티가 생기지 않고 `cn.ts`도 손대지 않는다.
- 기준을 세워놓고 조건이 충족됐는데 미루면 기준이 무의미해진다. 그래서 지금 한다.

이로써 §7.1 보완 토큰은 **8개**다. PM이 PRD v1.3에 반영한다.

### 2.2 reduce에서 독 모션 0.01s

알약 슬라이드(`0.24s`)와 `dockPop`을 reduce에서 `0.01s`로 줄인다(정지가 아니다).

**판단 기준을 세운다 — 모션이 곧 정보인 것만 reduce에서 남긴다.**
스피너는 회전 자체가 "진행 중"이라는 정보라서 남겼다. 알약은 **최종 위치**가 정보이고,
활성 탭은 배경·굵기·색으로 그대로 전달된다. 모션을 없애도 잃는 정보가 없다.
`rise`와 같은 처리다.

## §3 오버레이 루트 — `AppShell` 수정

세 컴포넌트 모두 스테이지 안에 떠야 한다. `position: fixed`로 두면 1024px 화면에서
430px 스테이지를 벗어난다(W-03B §4-9와 같은 이유).

`AppShell`에 오버레이 루트를 추가한다.

```tsx
// AppShell.tsx
export const OverlayRootContext = createContext<HTMLElement | null>(null);

// 스테이지 안, 스크롤 영역 바깥에 배치
const [overlayEl, setOverlayEl] = useState<HTMLElement | null>(null);
<div ref={setOverlayEl} aria-hidden={false} /* position:absolute; inset:0; pointer-events:none */ />
<OverlayRootContext.Provider value={overlayEl}>{children}</OverlayRootContext.Provider>
```

- 오버레이 3종은 `useContext(OverlayRootContext)` → `createPortal`. 값이 `null`인 첫 렌더에는
  `null`을 반환한다.
- 루트 자체는 `pointer-events: none`, 실제 딤·카드만 `auto`로 되돌린다.
- **`document.getElementById`로 찾지 마라.** 첫 렌더에 없다.
- z-index는 §6.4 값을 그대로 쓴다: 토스트 `60` · 모달 `55` · 시트 `50` · 딤 `40`.
- `AppShellProps`에 prop을 추가하지 마라. 내부 구조 변경만이다.

## §4 `Toast` — `src/components/Toast.tsx`

PRD §6.4 + §8.10.1 문구 사전 + Claude Design **P-03 [5]**.

### 4.1 규격

| 항목 | 값 |
| --- | --- |
| 위치 | 상단 `calc(env(safe-area-inset-top) + 18px)`, 가로 중앙, `z-index 60` |
| 컨테이너 | `radius 999`(`rounded-pill`), `padding 11px 18px` |
| 배경 | `rgba(31,81,56,0.92)` + `backdrop-filter: blur(12px)` |
| 그림자 | `0 14px 34px rgba(20,53,38,0.35)` |
| 텍스트 | 흰색 `13px/500` |
| 아이콘 | 좌측 체크 `14px` 흰색 |
| 모션 | 진입 `0.3s ease`. **2.2초** 후 자동 소멸 |
| 동시 표시 | **1개만.** 새 토스트가 오면 기존 것을 즉시 교체한다 |
| 접근성 | `role="status"` + `aria-live="polite"` (§15.3). 아이콘은 `aria-hidden` |

`13px`은 토큰에 없다. `text-row`(14.5) / `text-label`(12) 어느 쪽도 아니므로
**인라인 `text-[13px]`로 두고 보고서에 적는다.** 새 토큰을 만들지 마라(1회 사용).

### 4.2 API — 타이머와 교체 규칙을 컴포넌트가 소유한다

화면마다 `setTimeout`을 다시 짜면 2.2초·교체 규칙이 갈라진다(`Field` 검증 타이밍과 같은 논리).

```ts
// src/components/Toast.tsx
export function ToastProvider({ children }: { children: ReactNode }): JSX.Element;
export function useToast(): (message: string) => void;
```

- 큐를 만들지 마라. 새 메시지는 **기존 것을 즉시 교체**한다(§6.4 명시).
- 교체 시 진입 모션을 다시 태운다. 같은 메시지가 연속으로 와도 재생되어야 한다.
- `ToastProvider`는 스토리 페이지에서 `AppShell` 안쪽에 둔다(오버레이 루트가 필요하다).

### 4.3 문구

§8.10.1 사전(TS-01~TS-21)의 문자열만 쓴다. 스토리 페이지에서는 TS-01·TS-02·TS-12를 예시로 쓴다.
**컴포넌트 안에 문구를 하드코딩하지 마라.** 호출부가 넘긴다.

## §5 `BottomSheet` — `src/components/BottomSheet.tsx`

PRD §6.4 + §7.4 + §15.3.

### 5.1 규격

| 항목 | 값 |
| --- | --- |
| 시트 | 상단 `radius 26`(`rounded-26`), 배경 `--color-sundo-sheet`, `backdrop-filter: blur(24px) saturate(180%)` |
| 내부 하이라이트 | `--highlight-top` (§2.1) |
| 패딩 | `12px 22px`, 하단 `calc(env(safe-area-inset-bottom) + 26px)` |
| 그랩 핸들 | 상단 중앙 `38 × 4.5`, `radius 999` |
| 딤 | `rgba(20,53,38,0.30)` + `backdrop-filter: blur(3px)`, `z-index 40` |
| 시트 모션 | `0.38s cubic-bezier(.2,.8,.25,1)`, `translateY(110%) ↔ 0` |
| 딤 모션 | `0.3s`, `opacity 0 ↔ 1` |
| z-index | 시트 `50` |

### 5.2 거동

- **딤 탭 → 닫기**(§6.4 명시).
- **ESC → 닫기**(AC-09).
- `role="dialog"` + `aria-modal="true"` + `aria-labelledby`(제목 연결).
- **포커스 트랩.** 열릴 때 시트 안 첫 포커스 가능 요소로, **닫을 때 트리거 요소로 복귀**(§15.3).
- 배경 스크롤 차단 — 딤이 `position: absolute; inset: 0; touch-action: none`으로 막히는지
  **실측하라.** 부족하면 스크롤 영역에 `overflow: hidden`을 걸고 보고서에 적는다.
- reduce에서 시트·딤을 `0.01s`로(§7.4 AC-07이 "화면 전환·시트는 0.01s"로 명시).

### 5.3 API

```ts
interface BottomSheetProps {
  open: boolean;
  onClose: () => void;
  title?: string;          // 있으면 그랩 핸들 아래 19px/700 (text-sheet)
  children: ReactNode;
}
```

- **`popstate` 연동(N-02)은 이번에 하지 마라.** React Router가 들어오면 history 조작이 겹친다.
  W-05에서 붙인다.
- 키보드 높이 대응(AC-12)은 W-09다.
- 드래그로 닫기는 규격에 없다. **만들지 마라.**

## §6 `ConfirmModal` — `src/components/ConfirmModal.tsx`

PRD §6.4 + §8.10.4 사전 + Claude Design **P-04**. 채택 산출물 `4a`~`4f`, `20c`.

### 6.1 규격 (P-04 원문)

| 항목 | 값 |
| --- | --- |
| 딤 | `rgba(20,53,38,0.30)` + `blur(3px)` |
| 카드 폭 | `화면 폭 − 88px` |
| 카드 위치 | 세로 중앙보다 살짝 위 (약 `45%`) |
| 카드 | `radius 24`, 배경 `rgba(255,255,255,0.92)` + `blur(24px) saturate(180%)`, 테두리 `1px rgba(255,255,255,0.9)`, 그림자 `0 20px 50px rgba(20,53,38,0.25)`, `padding 24px 22px` |
| 제목 | `17px/700` `--color-sundo-900`, 중앙 정렬 |
| 본문 | `12px` 아래, `14px/500` `--color-sundo-ink-70`, 중앙 정렬, 2줄 허용, `line-height 1.6` |
| 버튼 행 | `20px` 아래. 2개 가로 배치, `gap 10`, 각 `flex: 1`, 높이 `48`, `radius 14` |
| 좌 버튼 | line 스타일 `취소` — `13.5px/700` `--color-sundo-ink-70` |
| 우 버튼 | fill 스타일 — `13.5px/700` 흰색 |
| 파괴적 우 버튼 | `linear-gradient(160deg,#C0392B,#A93226)` |
| 모션 | 딤 `0.3s` 페이드. 카드 `scale(0.94) → 1` + `opacity 0 → 1`, `0.25s` |
| z-index | `55` |

> **`Pill` 컴포넌트를 쓰지 마라.** "line 스타일"·"fill 스타일"은 표면 처리를 가리키는 말이고,
> 모달 버튼은 높이 48 · `radius 14`라 `.pill`(radius 999)과 다르다. 별도 클래스로 만든다.

`17px` · `13.5px` · `14px`은 토큰에 없다. 인라인으로 두고 보고서에 적는다.
`linear-gradient(160deg,#C0392B,#A93226)`도 이 컴포넌트 전용 1회이므로 토큰화하지 않는다(§3 기준).

### 6.2 이번에 새로 확정하는 것 2건 — 보고서에 남겨라

규격에 없어 판단이 필요한 지점이다. 아래로 확정한다.

1. **초기 포커스는 좌측 `취소` 버튼에 둔다.** 파괴적 버튼에 포커스를 두면 Enter 오조작이 난다.
2. **딤 탭과 ESC는 `취소`와 같다**(닫기). 닫을 방법이 버튼뿐이면 키보드 사용자가 갇힌다(AC-09).
   `취소`가 비파괴적 기본값이므로 안전하다.

`role="dialog"` + `aria-modal="true"` + `aria-labelledby`(제목) + `aria-describedby`(본문).
포커스 트랩과 트리거 복귀는 `BottomSheet`와 같다 — **`src/lib/useFocusTrap.ts`로 공유하라**
(2개 컴포넌트에서 쓰이므로 §3 기준을 만족한다).

### 6.3 API

```ts
interface ConfirmModalProps {
  open: boolean;
  title: string;
  body: string;
  confirmLabel: string;
  onConfirm: () => void;
  onCancel: () => void;
  destructive?: boolean;   // true면 우 버튼 danger 그라디언트
  loading?: boolean;       // 실행 중 우 버튼 스피너 + 양쪽 비활성
}
```

- 좌 버튼 라벨은 항상 `취소`다(MD-01~MD-07 전부). prop으로 열지 마라.
- 스토리 페이지에서 **MD-01 ~ MD-07 7종을 전부 렌더**한다(§8.10.4 문구 그대로).
  `{이름}` 자리표시자는 `김부원`으로 채운다.
