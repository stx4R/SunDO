## §1 `.env.local` 채택 — 그대로 쓴다

PM이 `.env` 대신 `.env.local`에 6개 값을 채웠다. **바꾸지 마라. 오히려 이쪽이 낫다.**

- Vite는 `.env.local`을 전 모드에서 읽고 `.env`보다 우선순위가 높다.
- `.env.local`은 Vite 관례상 "값이 든 로컬 파일"이고, `*.local` 패턴에 이미 걸려 있다.
- `.env.example`을 복사가 아니라 이름 변경으로 만든 것을 발견해 원본을 복구한 판단이 맞다.
  ToDo 6단계 주석도 유효하다.

`src/lib/firebase.ts`는 `import.meta.env`를 읽으므로 파일명과 무관하다. 코드 변경 없음.

## §2 🔴 `.gitignore` — `.env.example`이 조용히 무시되고 있을 수 있다

보고에 "`.env.local`은 `*.local`·`.env.*` **양쪽에** 걸려 커밋되지 않는다"고 적혀 있다.
그렇다면 **`.env.example`도 `.env.*`에 걸린다.** 디스크에는 있는데 git이 추적하지 않는 상태이고,
그대로 커밋하면 DoD 3이 조용히 깨진다. 파일이 존재하니 육안으로는 정상으로 보인다.

**착수 즉시 확인하라.**

```
git check-ignore -v .env.local .env.example
```

`.env.example`이 무시 목록에 잡히면 `.gitignore`의 환경 변수 구간을 아래로 교체한다.

```gitignore
# 환경 변수 — 값이 든 파일은 전부 무시하고 예시만 추적한다
.env
.env.*
!.env.example
```

- **부정 패턴 `!.env.example`은 반드시 `.env.*` 뒤에 와야** 효력이 있다.
- 교체 후 재확인: `git check-ignore .env.example`이 **아무것도 출력하지 않아야** 한다.
- `git status`에 `.env.example`이 추적 대상으로 뜨는지도 함께 본다.
- `.env.local`은 계속 무시되어야 한다. 둘 다 만족하는지 확인하고 넘어가라.

이미 부정 패턴이 들어 있어 문제가 없으면 **손대지 말고** 확인 결과만 보고서에 적어라.

## §3 2단계에서 특히 조심할 것 3가지

### 3.1 `deleteUser` 직후 `rejectedEmail`이 날아가기 쉽다 (DoD 16)

`deleteUser` → `signOut` 순서로 가면 `onAuthStateChanged`가 `null`로 발화한다.
상태를 인증 상태에서 그대로 파생시켰다면 그 순간 `domainRejected`가 `signedOut`으로 덮이고
`rejectedEmail`도 사라진다. **화면에는 아무 일도 없었던 것처럼 보인다.**

S1의 거절 배너·거절 계정 칩(T-05)과 `다른 계정으로 로그인` 라벨 교체가 전부 이 값에 달려 있다.
`domainRejected`와 `rejectedEmail`은 **`clearRejection()`이 불릴 때까지 살아 있어야 한다.**
실측으로 확인하고, 덮이고 있었다면 고친 뒤 근거를 보고서에 적어라.

### 3.2 `permission-denied`를 `noProfile`로 뭉개지 마라 (DoD 19)

`users/{uid}` 조회는 두 가지 이유로 실패할 수 있다.

| 상황 | 올바른 판정 |
| --- | --- |
| 문서가 없다 (`exists() === false`) | `noProfile` → S2 가입 신청 |
| 조회가 **실패**했다 (`permission-denied`, 네트워크, 규칙 미게시) | `noProfile`이 **아니다** |

둘을 같게 다루면 **오프라인이나 규칙 오류일 때 활성 부원이 가입 신청 화면으로 튕긴다.**
`status`를 `noProfile`로 떨어뜨리지 말고 `errorCode`에 담아 구분하라. 구현 형태는 네가 정한다.

이번 검증에서도 중요하다 — 임시 Rules가 아직 게시 전이면 `permission-denied`가 나는데,
이걸 `noProfile`로 읽으면 **DoD 19가 거짓으로 통과한다.**

### 3.3 리다이렉트 왕복 (DoD 18)

`W-04_회신.md` §3의 진단 순서를 그대로 따른다. 환경 제약으로 판명되면 `보류(환경)`로 표시하고
W-19에서 재검증한다. **사전 승인된 사항이니 코드를 고치려 들지 마라.**
분기 로직(standalone 감지, 3개 에러 코드 → redirect 전환)과 실제 왕복은 나눠서 보고한다.
