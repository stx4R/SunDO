## 3. 토큰 승격 3종 (W-05 §5.3 후속)

W-03B §3 기준 — **서로 다른 컴포넌트 2개 이상에서 쓰이면 토큰**. S1이 2번째 사용처다.

| 값 | 1번째 사용 | 2번째 사용 | 조치 |
| --- | --- | --- | --- |
| `1.6875rem` (27px) / 700 | `.splash-title` | S1 앱 타이틀 (§8.1.2 #2) | `@theme`에 크기 토큰 신설 |

**규칙**

- 정의는 `@theme`에 **1곳**, Splash와 S1은 **둘 다 그 토큰을 참조**한다. 한쪽만 바꾸고 다른 쪽에 리터럴을 남기면 실패다.

- `--text-h1`(28px)로 27px를 대체하지 마라. 1px 차이라도 design 원문값이 우선이다.

### 5.1 `useOnline`

### 5.2 `OfflineBanner`

| 항목 | 값 (design P-03 [2] + PRD §6.4) |
| --- | --- |
| 위치 | 화면 최상단 safe-area 아래, 좌우 18px 여백 |
| 크기 | 높이 40px, `radius 14` |
| 배경 | `rgba(20,53,38,0.88)` + `blur 12` |
| 내용 | 좌측 16px 지점에 사선 그어진 와이파이 아이콘 14px 흰색, 그 우측 8px에 흰색 12px/700 |
| 문구 | `오프라인 상태입니다. 기록은 연결 시 자동 전송됩니다` |
| z-index | **70** |
| 마운트 | `OverlayRootContext`로 **포털**한다 |

**🟡 PRD와 design이 어긋나는 지점 1건 — 지시대로 처리하라.**
PRD §6.4는 `상단 고정 / z-index 70`이라 하고, design P-03 [2]는 `아래 콘텐츠를 밀어내는 형태(겹치지 않음)`라 한다. §0.3-1을 적용해 **PRD를 따른다** — 오버레이(absolute, z-70)로 띄우고 콘텐츠를 밀어내지 않는다. 밀어내기는 `AppShell`에 슬롯을 하나 더 요구하는데, S1은 세로 중앙 정렬이라 상단에 여유가 있어 겹침이 문제가 되지 않는다. **독이 있는 화면(W-08 이후)에서 H1과 겹치면 그때 재판단한다.** 이 판단을 보고서 §"판단이 필요했던 지점"에 적어라.

`.ovl-root`가 `pointer-events: none`인 것은 문제가 되지 않는다 — 이 배너에는 상호작용이 없다. **배너에 버튼·닫기를 붙이지 마라.**

## 6. S1 로그인 화면

`src/screens/Login.tsx`의 자리표시자를 실물로 교체한다. **§2.1에서 확보한 design 원문값이 1순위**이고, 아래 표는 그 값과 대조할 기준선이다.

### 6.1 구조 (위 → 아래)

| # | 요소 | 규격 |

| 6 | Footer(축약형) | 화면 **최하단**. §7 |
| 7 | 에러 배너 | 카드 **내부 최상단**. §6.4 |
| 8 | 거절 계정 칩 | 배너 아래 8px. §6.4 |

**레이아웃**: 세로 중앙 정렬이면서 Footer는 최하단이다. 1~5를 남는 공간에서 중앙 정렬하고 Footer를 흐름 마지막에 둔다. 200% 확대에서 넘치면 세로 스크롤로 대응하고 **가로 스크롤은 0이어야 한다**(AC-05).

**타이틀 스태거가 Splash와 다르다.** Splash는 `0 / .09 / .18 / .27 / .36`, S1은 `0.05`에서 시작해 `0.37`에서 끝난다(§8.1.2 #2 · design R-01 동일). **Splash 값을 복사해 오지 마라.** 두 값이 다른 것은 오류가 아니다.

### 6.3 문구 사전 — 이 문자열만 쓴다

§8.1.3 표가 S1의 사전이다. **§8.10.3에 재수록되지 않은 2건(`로그인 시도가 많습니다…`, `정지된 계정입니다…`)도 확정 문안이다** — §8 머리말이 그렇게 규정한다. 새 문구를 짓지 마라.

### 6.4 변형 5종과 우선순위

| 변형 | 판정 조건 | 화면 |
| --- | --- | --- |
| **A 기본** | 그 외 전부 | 배너·칩 없음 |
| **B 인증 중** | 로컬 `submitting` | 버튼 라벨 자리에 `#2E6B4C` 스피너 18px, 버튼 투명도 0.75, **재탭 차단**. 4-2 안내 줄 교체 |
| **C 도메인 거절** | `status === 'domainRejected'` | 배너 2줄(ER-11 + ER-12) + 거절 계정 칩 + **버튼 라벨을 `다른 계정으로 로그인`으로 교체** |
| **D 오프라인** | `!useOnline()` | `OfflineBanner` 노출 + 버튼 `opacity 0.45` + **탭 불가** + 4-2 안내 줄 교체 |
| **E 계정 정지** | `status === 'suspended'` | 배너 1줄. **보조 줄과 칩 없음** |

**우선순위** — 겹칠 수 있는 것은 D와 C·E뿐이다(C·E는 `status`가 서로 배타적이라 동시에 성립하지 않는다).

| 겹침 | 처리 |
| --- | --- |
| D + C | `OfflineBanner`와 도메인 거절 배너를 **둘 다** 그린다(서로 다른 층이다). 버튼 상태·4-2 안내 줄은 **D가 이긴다** |
| D + E | 동일 |
| D + B | 성립하지 않는다. 오프라인이면 버튼이 탭되지 않는다 |

**"탭 불가"의 정의**: 시각적으로 흐리기만 하는 것이 아니라 `disabled` 또는 그에 준하는 처리로 **`signIn`이 호출되지 않아야** 한다. DoD에서 호출 횟수로 검증한다.

**배너 규격 (design R-01 변형 C)**: `radius 12`, 배경 `rgba(192,57,43,0.10)`, `padding 11px 13px`. 좌측 느낌표 아이콘 14px `#C0392B`, 우측 세로 2줄 — 1줄 12px/700 `#C0392B`, 2줄 11px/500 `text-70`.

**거절 계정 칩 (design R-01 변형 C)**: `radius 999`, 배경 `rgba(20,53,38,0.06)`, `padding 6px 12px`. 좌측 회색 원형 18px 아바타 + 12px/500 `text-70`으로 `rejectedEmail`, 우측 X 아이콘 12px. **X는 터치 44×44를 확보**한다(§15.1 Footer 링크와 같은 방식 — 투명 패딩).
