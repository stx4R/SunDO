- 목록에는 **`status='active'` 전원**이 보인다(본인 포함)

- 하단 힌트 `부장 권한을 양도하면 내 계정은 일반 부원으로 전환됩니다`(§8.10.5)
  ⚠ Dev가 볼 때도 이 힌트는 그대로다 — **§8.10.5 확정 문안이라 바꾸지 않는다.** §7 신규 항목으로 올려라

### 3.3 `양도` pill의 렌더 조건

**pill이 렌더되는 조건 = 실행자 조건 ∧ 대상 조건.** 둘 다 만족해야 한다.

| 조건 | 내용 |
| --- | --- |
| 실행자 | `role === 'head'` **또는** `role === 'dev'` (결정 2) |
| 대상 (BR-20) | `status === 'active'` **且** `role ∈ { 'member', 'vice' }` |
| 대상 (R-08 · BR-59) | 🔴 **탈퇴 계정 제외** — `status`가 `active`가 아니므로 위 조건에 이미 포함된다 |
| 대상 (US-H-03 AC-4) | 🔴 **`pending` 제외** — 같은 이유로 포함된다 |
| 대상 (§8.8.3 #6) | 🔴 **본인 행은 `양도` 미표시** |

- Dev 본인은 `role === 'dev'`라 대상 조건에서 자동 제외된다. **별도 분기를 만들지 마라**
- 🔴 **`disabled`가 아니라 부재다**(W-15A §4-4)
- 오프라인에서는 `useOnline()`으로 **비활성**(배치는 오프라인에서 resolve되지 않는다 — W-15A §4-7)

### 3.5 🔴 양도 배치 — OP-11

**강등 대상은 「본인」이 아니라 「현재 부장」이다.** 그래야 head 경로와 Dev 경로가 한 형태로 통일된다.

```
현 부장 uid = departments/{deptId}.headUid          ← 🔴 본인 role로 추정하지 마라

writeBatch:
  users/{대상}        .role = 'head',   updatedAt
  users/{현 부장}     .role = 'member', updatedAt        ← head 실행이면 곧 본인
  departments/{id}    .headUid = {대상}, updatedAt
  auditLogs/{uuid}    action: 'HEAD_TRANSFER'
```

**커밋 전 확인 (W-15A §4-2 규약)**

1. `getDoc(users/{대상})` — 존재 · `status === 'active'` · `role ∈ {member, vice}`. 아니면 **E-3003** `양도할 수 없는 계정입니다`
2. `getDoc(users/{현 부장})` — 존재 · `role === 'head'`.
   🔴 **없거나 head가 아니면 그 연산만 빼고 승격만 진행한다**(BR-23의 부장 0명 복구 경로가 실제로 그 상태다).
   이 분기를 보고서에 남겨라
3. 대상이 본인이면 거부(BR-21 — 부장은 자기 역할을 직접 바꿀 수 없다)

**감사 로그** — `before { headUid: 현 부장 }` → `after { headUid: 대상 }`.
🔴 **이름·이메일을 담지 마라**(W-15A §4-9의 규율). `actorRole`이 `dev`면 그대로 기록된다(§4.1 · US-D-01 AC-2).

**🔴 클라이언트 배치는 「부장 정확히 1명」을 보장하지 못한다.** 두 연산이 원자적으로 함께 적용될 뿐,
같은 순간 다른 부장·Dev가 다른 사람에게 양도하는 경쟁은 막지 못한다.
**실질 보장은 Rules(§9.6 필수 조건 3)와 BR-23의 Dev 복구 경로다** — §5에 적어 규칙 회차로 넘겨라.

⚠ `refresh()`는 실패해도 `status`·`profile`을 흔들지 않는다(PROGRESS 확정). 실패하면 다음 진입에서 반영된다 — **재시도 루프를 만들지 마라.**

## 6. 검증 환경

W-15A와 같은 스텁 하네스다. **새로 필요한 것 3가지**만 적는다.

1. **역할 5종 × 3섹션 전수** — ②가 들어와 매트릭스가 커진다. 🔴 **Dev의 ② 양도 pill이 보여야 한다**(결정 2)
2. 🔴 **양도 경로 2종** — `head` 실행(본인 강등 + 화면 이동 + `refresh()`)과 `dev` 실행(남 강등 + 화면 유지).
   `refresh()`와 `navigate` **호출 순서**를 관측할 수 있어야 한다
3. **보정 회귀 측정** — S6 일시 · S9 요일 행 · S8 ③ 신청 행·`승인` pill의 computed를 **보정 전후로** 비교

**측정 함정 — W-15A가 남긴 5건을 그대로 적용한다.** 특히
③ **「강제 탭」을 `disabled = false` + `click()`으로 흉내 내지 마라** — React가 재렌더로 되돌린다
④ **사라지는 행의 애니메이션은 임시 노드로 재라**
⑤ **행 인덱스를 고정하지 마라** — 클라이언트 정렬이라 픽스처 순서와 다르다
① `__WRITES__`에서 **`useLastActiveAt`의 `users/{본인}` 쓰기를 걸러라** — 🔴 **이번엔 양도가 `users`를 2건 쓴다.**
본인 경로를 통째로 거르면 head 실행 시 **강등 연산이 사라져 보인다.** 경로가 아니라 **필드로** 갈라라
