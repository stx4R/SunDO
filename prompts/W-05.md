### 0.2 확인 요청 1·2번 근거

- **1번(스플래시)** — 스플래시는 **라우터가 아무것도 렌더하지 않는 동안** 보이는 화면이다.
  N-05는 라우팅보다 앞선 규칙이고, §6.4가 이를 `z-index 100` **전역 컴포넌트**로 규정한다.
  S1(W-06)이 소유하면 *S1이 마운트되기 전에 필요한 것을 S1이 갖는* 순환이 된다.
  → **W-05가 스플래시와 3초 타임아웃을 소유한다.**
- **2번(번들)** — 지금 화면이 0개라 라우트를 `lazy()`로 만들어도 **청크가 비어 있다.**
  덩치의 본체인 `firebase`는 `AuthProvider`가 루트에서 쓰므로 라우트 분할로 줄지 않는다.
  실효를 보려면 `firebase` 서브모듈 분리와 프리캐시 전략을 함께 봐야 하고 그건 W-16이다.
  → W-05는 **각 화면을 파일 1개 + `default export`로** 만들어 두기만 한다. 비용 0이고,
  W-16이 `lazy()`를 얹을 때 구조를 다시 뜯을 일이 없다.

### 0.3 🟡 §4-3에 남은 실제 위험 — 보고서에 기록만 하고 넘어간다

규칙을 `if false`로 막는 재현이 **두 번 다 `noProfile`로 나온 것**은 규칙 전파 지연이 아니라
**Firestore SDK가 캐시로 폴백했을 가능성이 높다.** `getDoc()`은 서버 실패 시 로컬 캐시로 떨어지고,
캐시가 "문서 없음"을 들고 있으면 **에러가 던져지지 않고 `exists() === false`가 반환된다.**

즉 결함 주입으로 증명한 분기는 옳지만, **실제 `permission-denied` 상황에서 그 분기가 타지 않을 수
있다.** 다만 이 폴백은 오프라인 지원(EC-01) 자체이기도 해서 지금 없앨 수 없다.

**이번에 고치지 마라.** `reports/W-05.md`와 `docs/PROGRESS.md`에 **W-17 항목**으로 남긴다 —
"인증 판정 시 `getDoc` 캐시 폴백 때문에 조회 실패가 문서 없음으로 보일 수 있다.
`getDocFromServer` 우선 + 실패 시 캐시 같은 전략을 W-17에서 판단한다."

### 0.4 이번 작업의 성격

지금까지는 컴포넌트를 만들었다. **W-05는 그것들을 처음으로 엮는다.**
`src/App.tsx` 스토리 페이지는 여기서 사라지고, 그 안의 W-03A~W-04 검증 표면도 함께 없어진다.
**지우기 전에 필요한 실측을 먼저 끝내라.**

`prefers-reduced-motion: reduce`에서 `0.01s`(AC-07 "화면 전환·시트는 0.01s").

## §5 스플래시 — `src/components/Splash.tsx`

§6.4(`z-index 100`, 최대 3초, 초과 시 오류 화면) + §8.1.5 + Claude Design **P-03 [1]**.

### 5.1 규격 (P-03 [1] — `10a`~`10d`에서 이식)

| 항목 | 값 |
| --- | --- |
| 로고 | 정중앙 원형 `84px`, 흰 배경, 그림자 `0 12px 26px rgba(31,81,56,0.25)` |
| 타이틀 | 로고 아래 `16px`, `자율생활부` `27px/700`, 글자 하나씩 순차 등장 |
| 부제 | 그 아래 `6px`, `대전대신고등학교` `13px` `--color-sundo-ink-70` |
| 점 3개 | 화면 하단 `100px`, `6px` 원형, `gap 8`, 순차 깜빡임(`pulseDot` 1.6s ease infinite) |

- 로고 자산이 없으면 **§8.1.2의 폴백**(`자` 이니셜 원형)을 쓴다. Footer와 같은 처리다.
- `pulseDot`은 §7.4 원문(`opacity 1→0.3→1`)을 이식한다. reduce에서 **정지**(AC-07 명시).
- 글자별 순차 등장은 `blurIn` 스태거를 재사용한다. reduce에서 `0.01s`.

### 5.2 3초 타임아웃

- `status === 'loading'`이 **3초를 넘기면** 오류 화면으로 전환한다.
- 문구는 `errorCode`로 고른다. 매핑이 없으면 **`ER-01 네트워크에 연결할 수 없습니다`**를 기본으로
  쓰고 어떤 코드가 매핑되지 않았는지 보고서에 적어라. **문구를 새로 짓지 마라**(§8.10.3 사전).
- 오류 화면에는 `다시 시도` 버튼(`NeuButton`)을 둔다. 탭하면 재판정을 시도한다.
- 타이머는 `loading`을 벗어나면 즉시 해제한다.

W-04 §4-3이 남긴 "판정이 확정되지 않는다"의 **탈출구가 이것이다.** 이게 없으면 조회가 계속
실패할 때 스플래시가 영원히 남는다.

## §6 `BottomSheet` — N-02 연동

시트가 열린 상태에서 뒤로가기를 하면 **화면 이동 없이 시트만 닫힌다.**

> 🔴 **`window.history.pushState`를 직접 쓰지 마라.** React Router가 history를 소유하고 있어
> 내부 상태와 어긋난다. 라우터의 `navigate`로 **같은 경로에 `state`를 얹어** 한 단계를 쌓고,
> `location.state`에서 그 표식이 사라지면 시트를 닫는다.

- 열 때: `navigate(location.pathname + location.search, { state: { ...location.state, sheet: <id> } })`
- 닫을 때(딤·ESC·프로그램): `navigate(-1)`로 되감아 히스토리를 맞춘다. **`open=false`만 내리면
  스택에 쓰레기가 남는다.**
- 뒤로가기: `location.state?.sheet`가 사라지면 `onClose`를 부른다.
- W-03C의 딤 탭·ESC·포커스 트랩·복귀는 **그대로 유지**한다. 회귀시키지 마라.

W-09에서 붙이지 않고 지금 하는 이유는, **history 소유권이 확정되는 시점이 지금**이기 때문이다.

## §7 `AuthProvider` · `ToastProvider` 배치와 `lastActiveAt`

- **둘 다 라우트 루트에 1개씩.** 화면마다 두면 전환할 때 토스트가 사라진다(W-03C §7-5).
- `ToastProvider`는 오버레이 루트가 필요하므로 **`AppShell` 안쪽**이어야 한다.
  `AppShell`이 라우트마다 있으므로 배치가 까다롭다 — **`AppShell`을 라우트 루트로 끌어올리고
  `hasDock`만 라우트별로 다르게 주는 구조**를 검토하라. 다른 방법을 택했다면 근거를 보고서에 적어라.
- **`lastActiveAt` 스로틀 갱신**(§9.3.1 — 앱 진입 시 1시간 스로틀)을 여기서 붙인다.
  W-04가 W-05로 넘긴 항목이다. `status === 'active'`일 때만 쓴다.

### 확인만 하고 보고할 것

`AuthProvider`가 `users/{uid}`를 **1회 `getDoc`으로 읽는지 `onSnapshot`으로 구독하는지** 확인하라.
구독이면 역할 변경이 실시간 반영되어 독이 자동 재구성된다(R-06). 1회 조회면 W-12에서
`getIdToken(true)` + 재조회를 붙여야 한다. **이번에 바꾸지 말고 어느 쪽인지만 보고하라.**
