### 5.2 `src/lib/parseDisplayName.ts` — 순수 함수

표시 이름 예: `26_20723유이준` (§9.4.1)

| ID | 규칙 |
| --- | --- |
| DR-08 | `^(\d{2})_(\d{5})(.+)$`. 그룹 3은 **트림 후 2~10자** |
| DR-09 | 그룹 2에서 DR-02로 `memberGrade`·`memberClassNo`·`memberNumber` 역파생 + DR-03 범위 검증 |
| DR-11 | 실패 시 `nameSource='manual'` 경로. **교사 계정이 이 경로를 타는 것이 정상이다** |

```ts
export type ParseFail = 'format' | 'nameLength' | 'range';
export type ParseResult =
  | { ok: true; academicYearShort: string; memberStudentNo: string; name: string;
      memberGrade: number; memberClassNo: number; memberNumber: number }
  | { ok: false; reason: ParseFail };

export function parseDisplayName(
  raw: string,
  classCountByGrade?: Record<number, number>,   // 없으면 반 1~10 (§9.4.1)
): ParseResult;
```

- **`classCountByGrade`를 선택 인자로 둔다.** 부서 문서가 로드되기 전에도 파싱해야 한다.
  없을 때 기본 범위는 `grade 1~3` · `classNo 1~10`(§9.4.1 "반(01~10)") · `number 1~99`.
- **DR-10 교차 검증은 여기서 하지 않는다.** 이메일이 필요하고, 불일치해도 가입을 막지 않는다.
  `AuthProvider`에서 `console.warn` 1회만 남긴다. 유급·전입 등 정당한 예외가 있다.
- `src/lib/studentNo.ts`에 DR-01·DR-02·DR-03을 분리해 두고 여기서 쓴다. W-08이 다시 쓴다.

### 5.3 도메인 3중 방어 — 2차(클라이언트)를 여기서 구현한다

| 층 | 위치 | 이번 작업 |
| --- | --- | --- |
| 1차 | OAuth `hd` 힌트 | §5.1 |
| **2차** | **클라이언트 재검증** | **여기** |
| 3차 | Security Rules | W-15 (임시 규칙은 §6) |

인증 성공 직후:

```
email = user.email.toLowerCase()
if (!/@dshs\.kr$/.test(email)) {
  await deleteUser(user)      // 순서 주의 — signOut 먼저 하면 권한이 사라진다
  await signOut(auth)
  → status 'domainRejected', rejectedEmail = email  (S1의 거절 계정 칩용, T-05)
}
```

- **정규식 끝의 `$`는 필수다.** 없으면 `attacker@dshs.kr.evil.com`이 통과한다(§9.6).
- `deleteUser`가 `auth/requires-recent-login`으로 실패할 수 있다. 실패해도 **반드시 `signOut`은 하고**
  거절 상태로 간다. 실패 사실은 보고서에 적어라.
- 소문자 정규화 후 비교한다(§9.3.1 `email` 제약).

### 5.4 팝업 / 리다이렉트

| 상황 | 처리 |
| --- | --- |
| 기본 | `signInWithPopup` |
| standalone 감지 | `window.matchMedia('(display-mode: standalone)').matches \|\| navigator.standalone` → **처음부터 `signInWithRedirect`** (EC-30) |
| `auth/popup-blocked` · `auth/cancelled-popup-request` · `auth/operation-not-supported-in-this-environment` | `signInWithRedirect` 폴백 |
| `auth/popup-closed-by-user` | 에러가 아니다. 취소로 처리하고 **TS-17** `로그인이 취소되었습니다`를 호출부가 띄울 수 있게 코드만 노출 |

ER-11~ER-14 · TS-17 문구는 W-06의 S1이 붙인다.

### 5.5 `AuthProvider`

`src/contexts/AuthProvider.tsx`. **PRD §6.1의 「인증 분기 규칙」 표를 읽고 그 분기와 1:1로 맞춰라.**
아래는 형태이지 정본이 아니다. 표와 어긋나면 **표를 따르고 차이를 보고서에 적어라.**

```ts
type AuthStatus =
  | 'loading'          // 판정 전 (N-05: 스플래시 유지)
  | 'signedOut'
  | 'domainRejected'   // §5.3
  | 'noProfile'        // users/{uid} 없음 → S2
  | 'pending' | 'active' | 'rejected' | 'suspended' | 'withdrawn';

interface AuthContextValue {
  status: AuthStatus;
  profile: UserProfile | null;      // users/{uid}
  parsed: ParseResult | null;
  rejectedEmail: string | null;     // T-05 거절 계정 칩
  errorCode: string | null;         // Firebase 에러 코드 원문
  signIn: () => Promise<void>;
  signOut: () => Promise<void>;
  clearRejection: () => void;       // T-06 칩 X
}
```

**DR-12 프로필 동기화** — 로그인할 때마다 표시 이름을 재파싱한다.

- `displayNameRaw`가 이전 값과 다르면 `name`·`memberStudentNo` 계열을 갱신한다.
- **`nameSource='manual'` 계정은 제외한다**(DR-13). 수동 입력값을 자동 파싱이 덮으면 안 된다.
- `PROFILE_SYNC` 감사 로그는 **W-04 범위 밖이다**(`auditLogs` 스키마·Rules가 아직 없다).
  갱신만 하고, 로그 항목은 보고서 §8에 미구현으로 남긴다.
- `lastActiveAt` 스로틀 갱신도 이번 범위 밖이다(→ W-05).

**금지** — `AuthProvider`가 화면을 그리거나 라우팅하지 않는다. 상태만 노출한다. 이동은 W-05다.

## §6 `database_ToDo/W-04_Firebase_콘솔.md` (WF-04)

PM이 콘솔에서 수행할 절차를 **단계 단위로** 적는다. 최소 항목:

1. Firebase 프로젝트 `sundo-dev` 생성 (프로덕션 `sundo-prod`는 W-19)
2. **Authentication → Sign-in method**
   - Google Provider **활성화**
   - **이메일/비밀번호 Provider가 비활성인지 확인**(C4 — 켜져 있으면 끈다)
3. **Authentication → Settings → Authorized domains** — `localhost` 확인, 배포 도메인은 W-19
4. **Firestore Database 생성 — 리전 `asia-northeast3`(서울), 프로덕션 모드**
   - ⚠ **테스트 모드로 만들지 마라.** 30일 뒤 전면 차단되고 그 사이 전부 공개된다.
5. **임시 개발용 Rules 배포** — 아래를 그대로 붙여넣게 하라.

```
// 임시 개발 규칙 — W-15에서 전면 교체한다. 절대 프로덕션에 배포하지 마라.
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null
        && request.auth.token.email.matches('.*@dshs[.]kr$');
    }
  }
}
```

6. 웹 앱 등록 → `firebaseConfig` 6개 값을 `.env`에 기입 (`.env.example` 참고)

**함께 명시할 것**

- 5번 규칙은 **도메인 3차 방어만 하는 최소 규칙**이다. 역할·상태 검증이 없다.
  **`sundo-dev`에 실제 학생 명부를 넣지 마라.** 시드는 W-15 이후다.
- 터미널 출력은 `Firebase에서 작업할 사항이 있습니다. Markdown File을 확인하세요` **한 줄만**(§20.2).
