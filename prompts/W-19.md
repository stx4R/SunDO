### 0.3 🔴 사용자 확정 결정 3건

**결정 1 — `sundo-dev-8ef38.web.app`에 배포하고 실기기에서 설치를 확인한다.**

`localhost`로는 PWA의 절반만 검증된다. iOS Safari는 `beforeinstallprompt`가 **없어서**
홈 화면 추가를 눈으로 봐야 한다.

🔴 **이 배포에 딸린 안전 조건 3가지 — 반드시 지켜라.**

| # | 조건 |
| --- | --- |
| 1 | 🔴 **URL을 부원들에게 공유하지 마라.** 검증용이다 |
| 2 | 🔴 **App Check와 BR-30 레이트 리밋이 없는 상태다.** 공개 URL + 활성 가입 코드 + 무제한 시도가 겹친다. **검증이 끝나면 활성 `inviteCodes`를 `isActive:false` + `revokedAt`으로 내려라**(문서는 지우지 않는다) |
| 3 | §18.4 「Rules·인덱스는 앱보다 먼저」 — 🔴 **이미 배포돼 있다**(W-16D). 앱 배포가 뒤인 것이 맞다 |

**결정 2 — 글꼴을 로컬 `@font-face`로 전환한다.**

`index.html:8`의 jsDelivr CDN을 걷고 `public/fonts/`의 TTF 5종을 쓴다.

🔴 **이 전환은 문서를 함께 고친다** — `src/lib/policy.ts`의
「글꼴 파일을 외부 배포처에서 내려받습니다」가 **거짓이 된다.** §3.4 참조.

⚠ **용량을 먼저 재라.** TTF 5종이 그대로면 무겁다. `woff2` 전환·서브셋을 판단하고
**근거와 실측을 남겨라.** 의존성 추가 0 규약이 걸린다면 §9로 물어라.

**결정 3 — 가입 동의 시각을 `users`에 저장한다.**

W-18 §8-2가 올린 「동의를 받았다를 증명할 수 없다」를 닫는다.

- `agreedAt`(서버 시각) + **동의 문서 버전** 2필드. 이름은 §9.3.1 규약에 맞춰 정하고 보고하라
- 🔴 **`users` create 규칙이 `hasOnly`를 쓰지 않는다**(W-18 §4.1 실측). 필드를 더해도
  **`firestore.rules` diff 0줄일 가능성이 높다** — 코드를 쓰기 전에 확인하고, 규칙을 넓혀야 한다면 §9로 물어라
- ⚠ **기존 계정 3개는 값이 없다.** 소급하지 마라 — 그것이 사실이다. 처리방침·약관에
  「동의 시점부터 기록한다」는 문장을 만들지도 마라(§8.10에 없다)

## 3. 구현 지시

### 3.1 manifest

- 이름·색·`display`·`start_url`·`scope`·`id`·`orientation`을 규격에서 가져온다.
  🔴 **규격에 없는 값은 만들지 말고 §9로 물어라**
- `theme_color`·`background_color`는 §7.1 토큰에서 빌린다. **값의 출처를 주석에** 남긴다
- 🔴 **`start_url`과 `scope`가 라우터와 어긋나면 설치 후 앱이 빈 화면으로 뜬다.** `router.tsx`의
  루트 경로와 대조하라

### 3.2 아이콘 — 🔴 생성 방법을 먼저 판단하고 근거를 남겨라

필요한 것: `192` · `512` · **maskable `512`** · `apple-touch-icon 180`.

- 🔴 **의존성 추가 0을 지킬 방법을 먼저 찾아라.** 이 저장소에는 CDP 하네스가 있다 —
  `favicon.svg`를 헤드리스 Chrome에 띄워 정확한 크기로 스크린샷하면 도구가 늘지 않는다
- maskable은 **안전 영역(중앙 80%)** 안에 로고가 들어와야 한다. 그냥 리사이즈하면 잘린다
- ⚠ `DSHS.png`를 쓰려면 §2.2의 확인이 먼저다. **출처가 불확실한 이미지를 배포하지 마라**
- 생성 결과를 **눈으로 확인**하라 — 배경 투명·여백·잘림

### 3.3 🔴 최소 서비스 워커 — 갱신 계약을 한 글자도 빼지 마라

이번 SW의 임무는 **「설치 가능하게 만드는 것」까지**다. 캐시 전략은 W-20이다.

| # | 계약 | 왜 |
| --- | --- | --- |
| 1 | 🔴 **캐시 이름에 버전을 넣는다** | 버전 없는 캐시는 W-20이 전략을 바꿀 때 지울 방법이 없다 |
| 2 | 🔴 **`activate`에서 옛 버전 캐시를 지운다** | 안 지우면 기기에 쌓인다 |
| 3 | 🔴 **새 SW가 즉시 활성화되는 경로를 확보한다** | `skipWaiting` + `clients.claim()`. **없으면 낡은 SW가 붙박이가 되어 그 기기는 새 배포를 못 받는다** |
| 4 | 🔴 **`unregister` 절차를 문서로 남긴다** | `database_ToDo/W-19.md`에. 되돌릴 수 없는 것을 배포할 때는 되돌리는 법을 먼저 적는다 |
| 5 | ⚠ **`index.html`을 캐시하지 마라** | W-20 전이고, 지금 캐시하면 새 배포가 사용자에게 안 간다 |
| 6 | **SW 등록 실패가 앱을 죽이면 안 된다** | `catch`로 삼키고 로그만 |

🔴 **`localhost`에서 등록·갱신·해제를 전부 확인한 뒤에 배포하라.** 배포 후에 알면 늦다.

### 3.4 🔴 글꼴 로컬 전환 — 문서를 함께 고친다

- `index.html`의 jsDelivr `<link>`를 걷고 `@font-face`를 `src/index.css`에 둔다
- ⚠ **CSS를 추가하면 번들에서 선택자 직전에 `@media`가 없는지 확인**(W-17 §4.1 규약)
- `font-display` 값을 판단하고 근거를 남겨라
- 🔴 **용량 실측** — 전환 전후의 총 전송량. `woff2`·서브셋을 판단하되 **의존성이 필요하면 §9로 물어라**
- 🔴 **`src/lib/policy.ts`에서 「글꼴 파일을 외부 배포처에서 내려받습니다」를 삭제하라.**
  `reports/W-18.md` §3.1의 사실 대조표에서 그 행도 함께 지운다.
  ⚠ **문장을 지우면서 다른 문장이 어긋나지 않는지** 대조표 전체를 훑어라

### 3.5 설치 안내 (S10)

- `홈 화면에 추가` 행의 `설치 안내` 칩이 **이미 있다**(W-17). 그 소비자를 만든다
- 🔴 **플랫폼이 갈린다** — Chrome/Android는 `beforeinstallprompt`를 잡아 둘 수 있고,
  iOS Safari는 **없다**. 안내 문구가 플랫폼마다 다르면 §8.10에 그 문구가 있는지 확인하라
- 🔴 **이미 설치된 상태**(`display-mode: standalone`)에서 이 행이 무엇을 보여야 하는지
  규격에서 확인하라. 없으면 §9로 물어라 — 만들지 마라
- standalone에서 `signInWithPopup`이 막히는지 확인하고, §9.1의 `signInWithRedirect` 폴백이
  **실제로 도는지** 실기기에서 본다
