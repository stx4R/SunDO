#### 프로브를 다시 쓸 일이 생기면 (W-13 이후)

W-10이 만든 `public/__w10probe.js`는 **고장 나 있다.** `projectId` 자리에 웹 API 키(`AIza…`)를 넣어 존재하지 않는 프로젝트 경로로 질의를 쐈고, 세 줄이 전부 `Permission denied on resource project AIza…`로 죽었다. **규칙 거부가 아니다** — 규칙 거부는 `Missing or insufficient permissions`다.

**저장소에 남아 있으면 삭제하라**(DoD 31). `public/`에 두면 번들에 섞여 배포된다.

다시 만든다면 요구는 넷이다.

1. **앱이 초기화한 SDK 인스턴스를 그대로 쓴다.** `lib/firebase`의 `db`를 import한다. config를 다시 조립하지 마라.
2. 🔴 **firestore 함수도 앱과 같은 모듈 인스턴스에서 가져와야 한다.** `/@id/firebase/firestore`로 import하면 **Vite가 별도 사본을 만들어** `collection(db, …)`이 `invalid-argument`를 뱉는다(실제로 겪었다). 해시가 매번 바뀌므로 경로를 하드코딩하지 말고 `performance.getEntriesByType('resource')`에서 실제 적재된 `firebase_firestore.js?v={해시}`를 찾아 그것을 import하라.
3. **머리글에 `db.app.options.projectId`를 찍는다.** `sundo-dev-8ef38`이 아니면 그 실행은 무효다.
4. **실패를 세 갈래로 분류한다** — `INDEX-REQ`(`failed-precondition`) / `RULES`(`permission-denied`) / `OTHER`. 지난번은 셋을 전부 `FAIL`로 뭉갰다.

### 2.2 🔴 `isActive`를 서버 질의에 넣지 않는다 — **§0.2가 결정했다**

W-10 §5.3의 학년 활성 판정이 `isActive==true`로 세므로 S5도 활성 학생만 보여야 한다. 「0명이라 회색인 학년인데 들어가면 학생이 보인다」가 되면 UI가 사실과 어긋난다(§0.5 예외 1). **여기까지는 그대로다.**

그런데 **어디서 거르느냐**가 §0.2로 갈렸다.

| 안 | 질의 | 필요한 인덱스 |
| --- | --- | --- |
| A — 서버에서 거른다 | `academicYear` + `grade` + `classNo` + `isActive` + orderBy `number` | **PRD에 없는 신규 인덱스**(W11-1) |
| **B — 클라이언트에서 거른다 (채택)** | `academicYear` + `grade` + `classNo` + orderBy `number` | **IX-08 그대로**(W11-2) |

**B로 간다.** 근거 셋이다.

1. **IX-08이 정확히 이 조합이다**(`academicYear ASC, grade ASC, classNo ASC, number ASC`). 새 인덱스를 만들지 않고 PRD 설계를 그대로 쓴다. A로 가면 §9.5에 없는 인덱스가 하나 늘고 PRD 이탈이 생긴다.
2. **한 반은 최대 37명이다**(`maxNumberPerClass`, D-04 확정). 비활성 몇 명을 더 읽는 비용이 무의미하게 작다.
3. **S3·S4의 활성 카운트는 서버에서 `isActive`를 쓴다**(W11-3이 인덱스 없이 통과했다). 거르는 위치가 달라도 **결과는 같다** — S4가 세는 수와 S5가 그리는 수가 일치한다. **이 일치를 DoD 12로 잠근다.**

> **IX-08에 `isActive`가 없다는 사실 자체는 §8 PRD 목록에 올려라.** 지금은 클라이언트 필터로 우회하지만, 명부가 1,033명 규모로 차고 전출이 누적되면 재검토 지점이 된다.

### 2.3 정렬 키 — `orderBy('number')`를 쓴다

§8.5.3은 `studentNo` 오름차순이라 하고 IX-08은 `number ASC`로 끝난다.

**`academicYear`·`grade`·`classNo`가 등식으로 고정된 상태에서 `number` 순서와 `studentNo` 순서는 동일하다.** DR-01이 `studentNo = grade + pad2(classNo) + pad2(number)`이므로 앞 3자리가 상수다. 설계된 인덱스를 쓰면서 §8.5.3의 요구를 충족한다. **이 등가성의 근거를 보고서에 적고, 스텁 12건으로 실측하라**(DoD 13).
