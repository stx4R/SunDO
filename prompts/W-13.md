### 0.2 사용자 확정 결정 3건

**결정 1 — `recordCount`는 A안이다.** §9.6 자기 갱신 허용 키에 `recordCount`를 추가하고
`request.resource.data.recordCount == resource.data.recordCount + 1` 조건을 건다.
🔴 **그러나 W-13은 그 코드를 붙이지 않는다.** S7은 조회 전용이고, 증가가 붙을 자리는 S6 저장 경로다.
**순서가 중요하다 — 규칙을 먼저 열고, 그다음 코드가 올린다.** 반대로 하면 W-15 배포 시점에 저장이 막힌다.
→ **W-15가 「규칙 배포 + S6에 증가 한 줄」을 같은 회차에 소유하고, 감소(OP-07)는 v1.1 삭제 회차가 소유한다.**
이번 회차는 `database_ToDo/W-13.md`에 그 순서를 못 박기만 한다.

**결정 2 — 학생 명부는 1개 반을 콘솔로 시딩한다(A안).** 절차는 `database_ToDo/W-12.md` §6에 있다.
시딩이 끝나면 **「인덱스 없이 실제로 동작」 미측정 1건이 실기기 저장 1회로 닫힌다.**
⚠ 시딩 완료 여부와 **무관하게** 이번 회차의 검증은 전부 스텁 하네스다. 시딩을 기다리지 마라.

**결정 3 — W-13 범위는 조회만이다.** 기록 수정·삭제·액션 시트·사유 변경 시트는 **v1.1**이다(§17.1 · §17.2).

### 2.3 실시간 구독 계약 — 실측으로 확정한다

W-12 §1-3이 오프라인 쓰기 계약을 실측으로 확정한 것과 같은 방식으로, 아래를 재고 조사에서 확정한다.

1. `onSnapshot`이 **첫 콜백을 캐시에서 먼저 주는지**(`metadata.fromCache === true`) 그리고 서버 응답 후 다시 부르는지
2. `metadata.hasPendingWrites` — **S6가 방금 만든 로컬 문서**가 구독에 즉시 들어오는지
3. 오프라인 전환 시 구독이 **에러로 끊기는지, 캐시로 계속 응답하는지**
4. `unsubscribe()` 호출 후 콜백이 더 오지 않는지

→ 이 결과가 §3.2(동기화 칩 4상태)와 §3.7(구독 수명)의 근거다.

### 2.4 질의 형태와 인덱스

| 질의 | 형태 | 인덱스 |
| --- | --- | --- |
| 목록 (전체) | `where academicYear == · where status == 'active' · orderBy occurredAt desc · limit 30` | 🔴 **IX-01 필요** |
| 목록 (사유 필터) | 위 + `where reasonCode ==` | 🔴 **IX-02 필요** |
| 카운터 오늘·주·달 | `where status == 'active' · where {date\|week\|month}Key ==` — **등식 2개** | **불필요** (W-10 실측 W10-1·W10-2 선례) |
| 작성자 상태 | `users` 문서 ID `in` 묶음 | 불필요 |

🔴 **IX-01·IX-02는 아직 생성돼 있지 않다**(`database_ToDo/W-12.md` §1).
**스텁 검증은 인덱스와 무관하므로 코드는 진행한다.** 대신 **인덱스가 없을 때 실기기에서 무슨 일이 나는지**를
§3.10의 에러 경로로 반드시 덮어라 — `failed-precondition`이 **ER-02로 떨어져야 하고 EM-02로 떨어지면 안 된다**(DoD 17).

**시간 범위 조건은 걸지 않는다.** §8.7.3의 「기본 최근 30일」은 `limit(30)` 페이지네이션이 이미 만족하며,
범위 조건을 걸면 무한 스크롤이 그 경계를 넘지 못한다. **§7에 문언 정정 후보로 올려라.**

### 3.7 🔴 실시간 구독 + 페이지네이션

**규칙을 그대로 따른다.**

1. **구독은 첫 페이지에만 건다** — `limit(30)` 질의에 `onSnapshot` 1개
2. **`더 보기`로 불러온 과거 페이지는 `getDocs` 정적 배열**이다. 구독하지 않는다
3. **병합은 문서 ID 기준 `Map`**이다. 구독 결과가 정적 페이지와 겹쳐도 중복 행이 생기지 않는다
4. **커서는 첫 페이지의 마지막 문서**(`startAfter`)다. 새 기록이 들어와 첫 페이지가 밀려도 커서는 고정이므로 구멍이 생기지 않는다
5. **필터를 바꾸면 이전 구독을 해제하고 새로 건다.** 정적 페이지는 버리고 커서를 초기화한다
6. 🔴 **언마운트에서 반드시 `unsubscribe()`** 한다. 독 이동은 `replace`라 화면이 언마운트된다 —
   해제하지 않으면 탭을 오갈 때마다 구독이 쌓인다
7. 신규 수신 행은 최상단에 삽입하고 **`rise` 0.3s**(T-03)
8. 🔴 **구독은 정확히 1개다.** 카운터·작성자 상태는 구독하지 않는다(단발 조회 + 로컬 증감)

⚠ **이 형태가 성립하지 않는다고 판단되면 코드를 쓰기 전에 물어라.** 대안(전 페이지 구독 / 구독 없이 당겨서 새로고침)은
각각 비용이 다르고, 되돌리기 비용은 `records.ts` 함수 1개다.

## 6. 검증 환경

W-12와 같은 스텁 하네스다. **새로 필요한 것 4가지**만 적는다.

1. **`onSnapshot` 스텁** — 초기 캐시 콜백 → 서버 콜백 순서, `metadata.fromCache`·`hasPendingWrites` 주입,
   외부에서 **신규 문서를 밀어 넣어** T-03을 재현, `unsubscribe()` 후 콜백 중단 관측
2. **`orderBy` + `limit` + `startAfter` 해석** — 페이지네이션 커서가 실제로 동작해야 무한 스크롤 DoD가 성립한다
3. **`getCountFromServer` 스텁** — 카운터 3종
4. **오류 주입** — `failed-precondition`·`permission-denied`·`unavailable`을 목록 질의에 개별 주입

**측정 함정 — W-12가 남긴 4건을 그대로 적용한다.**
① 히스토리 검증은 앱 내비게이션으로 진입 ② `__WRITES__`는 `records/` 경로만 세기(`useLastActiveAt`가 상시로 쓴다)
③ 전이 지속시간은 전이가 끝난 뒤 읽기 ④ `delayMs`는 인증 `getDoc`에도 걸린다 / **조건을 못 만든 검증은 미측정이다**
