  `anonymizedAt` null · 변경 필드 부분집합)을 **전부** 만족할 때만 연다.
  `createdAt`·`recordCount`·`email`·`uid`는 불변이다. **규칙 작성은 W-15**이고 요청서는 `database_ToDo/W-08.md`.
- **제출 버튼 활성 조건은 "9자 완성"이지 "검증 성공"이 아니다.** (W-08 §5-1)
  design `13d`(검증 실패인데 버튼 활성)와 `13b`(7자인데 비활성)를 동시에 만족하는 규칙이 이것뿐이고,
  "검증 성공일 때만"으로 하면 **다 치고 바로 누르는 동선에서 탭이 버튼에 닿지 않아 blur도 안 일어난다.**
  형식이 틀린 9자도 활성으로 두고 탭하면 형식 에러가 뜨게 한다. 서버 재판정은 제출 때 어차피 돈다.

  화면은 `input` 요소에 닿을 수 없다 — 캐럿 복원은 `Field`의 `useLayoutEffect`가 한다.
  **의존성 배열을 붙이지 마라** — 변형 결과가 직전 값과 같으면 리렌더가 생략되고, 그때 DOM에만
  버려진 원문이 남는다. `FieldHandle.reset()`은 "판정 없음"을 그리는 유일한 수단이다(조회 실패).
- **조회 실패를 "없는 코드"로 읽지 않는다.** (W-08 §3.1) `lookupInviteCode`는 `null`이 아니라
  **판별 가능한 유니온**(`ok`·`missing`·`unusable`·`failed`)을 돌려준다. `failed`는 인라인 에러가
  아니라 **상단 배너 ER-01**로 가고 필드는 검증 이전 상태로 되돌린다.
  🟡 단 `getDoc` 캐시 폴백 때문에 SDK 계층에서 무력화될 수 있다 — W-17 항목과 같이 봐야 한다.
- **S2에 오프라인 배너를 붙이지 않았다.** (W-08 §5-7) `.ofb`(`safe-area+16px`)가 S2의 헤더
  (`safe-area+26px`)와 **실제로 겹치는 첫 화면**이다. 겹침 해소는 `AppShell` 슬롯 신설이 필요해
  유예했고, 대신 §8.2.5의 **힌트 교체 + 버튼 비활성**으로 오프라인을 알린다.

- **포커스 테두리 1.5px는 `border-width`가 아니라 inset 그림자로 낸다.** (W-03A §4-3)
  `border-width`를 바꾸면 padding box가 줄어 라벨 기준선이 흔들린다. 되돌리지 말 것.
- **`.ff-ro`의 "테두리 없음"은 `border: 1px solid transparent`다.** (W-03A §4-1)
  `border: 0`으로 지우면 읽기 전용만 라벨 좌측 기준선이 1px 어긋난다.
- **reduce에서 스피너는 정지시키지 않는다.** (W-03A §4-4) 진행 중을 알리는 유일한 피드백이다.
- **성공 상태는 blur에서만 켠다.** (W-03A §4-2 → **W-03B §1에서 수정**)
  `ref.validate()`(제출)도 성공 체크를 켜지 않는다. 제출 시점의 주인공은 에러다.
  단 **켜져 있던 성공을 끄지도 않는다** — 해제는 값 변경만 담당한다.
- **`-webkit-` 접두사를 손으로 적지 않는다.** (W-03B §4-1)
  표준과 나란히 적으면 lightningcss가 둘을 같은 속성으로 보고 **표준 선언을 지운다.**
  표준만 적으면 접두사판을 자동으로 덧붙인다. `backdrop-filter`에서 실제로 터졌다.
- **reduce에서 덮어야 하는 값은 인라인 `style`로 주지 않는다.** (W-03B §4-3)
  인라인은 미디어 쿼리가 이길 수 없다. 커스텀 속성(`--rise-delay`)으로 넘긴다.
- **`ResizeObserver` + `setState`는 결과를 폭에서 직접 계산한다.** (W-03B §4-2)
  직전 상태에서 한 칸씩 움직이면 경계 폭에서 무한 루프가 된다(React #185 — 실제로 380px에서 앱이 죽었다).
  `space-around`의 항목 사이 간격은 `free / n`이다(`n-1`이 아니다).
- **독 활성 배경은 항목이 아니라 절대 위치 알약 1개가 갖는다.** (PRD §6.2 · design `15d`)
  항목마다 배경을 켜고 끄면 가로 슬라이드가 불가능하다.
- **독 비활성 라벨 `rgba(20,53,38,0.5)`은 §15.2 AC-01과 충돌하는 채로 뒀다.** (W-03B §7)
  §6.2 원문을 따랐다. **임의로 0.70으로 올리지 말 것.** W-18 대비 실측에서 재판정한다.
- **Footer 링크 44px은 투명 패딩 + 음수 마진으로 낸다.** (W-03B §4-7)
  `padding: 15px 0` + `margin-block: -15px`. 시각 높이 14px이 유지돼야 접힘 줄 간격이 10px이 된다.
- **`fs.rmSync`가 이 환경(Node v24.2.0/Windows)에서 프로세스째 죽는다.** (W-03C §4-1)
  재귀가 아니라 파일 1개여도 exit 127(`0xC0000409`). `fs.promises.rm`·`unlinkSync`는 정상이다.
  vite `emptyOutDir`가 `rmSync`를 쓰기 때문에 `dist/`가 남아 있으면 빌드가 통째로 죽었다.
  **W-03B가 OneDrive를 원인으로 지목한 것은 오진이다.** `build` 스크립트가 선삭제로 막는다.
- **오버레이 3종은 스테이지 안 `absolute`다.** (W-03C §3·§4-2)
  `AppShell`의 오버레이 루트에 `createPortal`한다. `fixed`로 두면 430px 밖에서 스테이지를 벗어난다.
  루트는 스크롤 영역의 **형제**여야 딤이 배경 스크롤을 막는다. 루트에 `z-index`를 주지 마라.
- **포커스 트랩은 `open && mounted`로 건다.** (W-03C §4-3)
  `open`만 보면 마운트 전 렌더에서 ref가 비어 조기 반환하고, 이후 다시 돌지 않아 트랩이 죽는다.
- **토스트는 큐가 없다.** (W-03C §4-10) 새 메시지가 기존을 즉시 교체하고 `key`가 바뀌어 모션이 다시 돈다.
- **모달 버튼에 `Pill`을 쓰지 않는다.** (W-03C §4-8)
  "line/fill 스타일"은 표면 처리를 가리키는 말이고 모달 버튼은 높이 48 · radius 14다.
- **확인 모달의 초기 포커스는 좌측 `취소`, 딤 탭·ESC도 취소다.** (W-03C §4-7)
  파괴적 버튼에 포커스를 두면 Enter 오조작이 난다. 좌 버튼 라벨은 항상 `취소`이며 prop으로 열지 않는다.
- **충돌 해소 순서가 확정됐다.** (W-04 지시서 §0.2)
  1) PRD가 명시한 값이 있고 design이 그 손실 없는 이형이 아니면 → **PRD**
  2) PRD 표기가 design의 축약·전사로 보이면 → **design**
  3) PRD가 침묵하면 → **design**(DS-01)  4) 둘 다 없으면 → 멈추고 질문(QA-01)

## 참고
- **`src/App.tsx` 스토리 페이지는 W-05에서 사라졌다.** 필요하면 `git show 1e06962:src/App.tsx`.
  `App.tsx` 주석에도 같은 명령을 적어 뒀다. 되돌리기 비용은 한 줄이다.
- **`AuthProvider`는 `users/{uid}`를 `getDoc` 1회로 읽는다. 구독이 아니다.** (W-05 §6)
  역할 변경이 실시간 반영되지 않는다. R-06의 `getIdToken(true)` + 재조회는 **W-12**가 붙인다.
- **🟡 W-17 항목 — `getDoc` 캐시 폴백.** (W-05 §9 · W-05 지시서 §0.3)
  인증 판정 시 캐시 폴백 때문에 **조회 실패가 "문서 없음"으로 보일 수 있다.**
  `getDoc()`은 서버 실패 시 로컬 캐시로 떨어지고, 캐시가 "문서 없음"을 들고 있으면
  에러가 던져지지 않고 `exists() === false`가 반환된다. W-04 §4-3의 분기는 옳지만
  실제 `permission-denied`에서 안 탈 수 있다 — 활성 부원이 가입 신청 화면으로 튕긴다.
  **지금 없앨 수 없다.** 그 폴백이 곧 오프라인 지원(EC-01)이다.
  W-17에서 `getDocFromServer` 우선 + 실패 시 캐시 같은 전략을 판단한다.
  이 위험이 실현되면 W-05 §7의 `permission-denied` 문구 문제도 함께 사라진다. 두 항목을 같이 봐야 한다.
- **실측 방법(W-05).** `vite preview`가 SPA 폴백을 하므로 **모든 경로를 실제 URL 직접 진입**으로 쟀다.
  `status`·`role` 주입은 임시 `ProbeAuthProvider`가 맡았고(AuthContext를 임시 export),
  측정 후 4곳 전부 되돌렸다. **프로브 제거 후 빌드 산출물 해시가 도입 전과 같은 것이 제거의 증거다.**
- W-01 착수 시 원격 저장소가 비어 있지 않아(커밋 27개) 사용자 선택에 따라 히스토리를
  리셋하고 v0.0.1 단일 커밋으로 시작했다.
  기존 원격 히스토리 백업: `바탕 화면/SunDO_remote_backup_20260820.bundle`
  (복원: `git clone SunDO_remote_backup_20260820.bundle`)
- `design/index.html`은 번들 아티팩트라 마크업이 JSON 문자열로 인코딩돼 있다.
  CSS를 꺼내려면 이스케이프를 2단계 해제해야 한다. 방법은 `reports/W-02.md` §5 서두 참조.
- **검증 환경 주의.** W-02는 Chrome 확장으로 `getComputedStyle`을 읽었으나 W-03A 재개 세션에서는
  확장이 연결돼 있지 않았다. 헤드리스 Chrome을 CDP로 직접 구동해 같은 측정을 했다
  (의존성 추가 없음, node 전역 `WebSocket`/`fetch`만 사용). 방법은 `reports/W-03A.md` §1 참조.
  - 헤드리스는 창이 활성이 아니면 `focus`/`blur` 이벤트가 **발생하지 않는다.**
    `Emulation.setFocusEmulationEnabled`를 켜야 blur 검증을 실측할 수 있다.
- ~~`src/App.tsx`는 스토리 페이지다~~ → **W-05에서 라우터 루트로 대체됐다.**
- **순수 함수 실측 방법(W-04).** 테스트 러너가 없어 Node의 타입 스트리핑으로 `src/lib/*.ts`를
  직접 import해 실행했다. 확장자 없는 상대 import는 `module.register` 해석 훅으로 `.ts`를 붙였다.
  소스를 복사하지 않으므로 실측 대상과 저장소 파일이 어긋나지 않는다. 스크립트는 스크래치패드에 있다.
- **최소 지원 폭은 360px이다.** (W-03C 지시서 §0.2) 320px에서 독 간격이 0이 되는 것은 지원 범위 밖이다.
- **토큰화 기준(W-03B 지시서 §3)**: 서로 다른 컴포넌트 2개 이상에서 쓰이면 토큰.

  `inset 0 1px 0 rgba(255,255,255,0.28)`(`.btnp`+모달 버튼 2종 3회),
  **`rgba(46,107,76,0.22)`**(스피너 트랙 — `.ff-spin`·`.gbtn-spin` 2개 컴포넌트, W-06에서 2번째 사용처 발생).
