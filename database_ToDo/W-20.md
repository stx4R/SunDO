## 1. 🔴 서비스 워커 해제 — 캐시가 붙은 판본

### 1.1 무엇이 달라졌나

| | W-19 (`v0.12.0`) | **W-20 (`v0.13.0`)** |
| --- | --- | --- |
| 캐시 | **없음**(`caches.open` 0건) | 🔴 **있음** — `sundo-shell-v0.13.0-{해시}` |
| 담기는 것 | — | `/index.html` + `/assets/**`(설치 시) · `/fonts/`·`/icons/`·`/favicon.ico`(쓸 때) |
| 낡은 워커가 남으면 | 증상 없음 | 🔴 **낡은 앱 셸을 붙들 수 있다** |

⚠ 다만 **내비게이션이 network-first**라, 온라인이면 낡은 워커라도 **새 `index.html`과
새 해시 자산을 받아 온다.** 화면은 최신이고 낡은 것은 워커 코드뿐이다.
그래도 아래 절차가 필요한 경우는 **캐시 자체가 잘못 담겼을 때**다.

### 1.2 사용자가 직접 지우는 법 (Android Chrome · 데스크톱 Chrome)

1. 주소창에 `chrome://serviceworker-internals` → `sundo-dev-8ef38.web.app` → **`Unregister`**
2. 주소창 좌측 자물쇠(또는 ⓘ) → `쿠키 및 사이트 데이터` → **`사이트 데이터 삭제`**
   🔴 **2번을 건너뛰지 마라.** 1번은 워커만 지우고 **캐시는 남긴다.**
3. 탭을 **전부 닫았다가** 다시 연다

**DevTools**: `F12` → `Application` → `Service Workers` → `Unregister` →
`Storage` → **`Clear site data`**(`Cache storage` 체크 확인)

### 1.3 iOS Safari

1. 설정 → Safari → **고급** → **웹사이트 데이터** → `sundo-dev-8ef38.web.app` 스와이프 삭제
2. 홈 화면 아이콘이 있으면 **아이콘도 지우고 다시 추가**

### 1.4 🔴 원격으로 되돌리는 법 — 자기 제거 워커

사용자에게 「지워 주세요」라고 말할 수 없을 때의 유일한 탈출구다.
**워커를 없애지 말고, 자기를 지우는 워커를 같은 URL에 배포한다.**

`public/sw.js`를 **통째로** 아래로 바꾸고 `firebase deploy --only hosting`.

```js
self.addEventListener('install', () => self.skipWaiting())
self.addEventListener('activate', (event) => {
  event.waitUntil((async () => {
    const names = await caches.keys()
    await Promise.all(names.map((n) => caches.delete(n)))
    await self.registration.unregister()
    const clients = await self.clients.matchAll({ type: 'window' })
    for (const client of clients) client.navigate(client.url)
  })())
})
```

🔬 **W-20에서 캐시가 붙은 상태로 실측했다** — 실행 뒤
`registration: null` · `caches: []` · `controller: false`.
⇒ 이 절차는 **캐시가 생긴 뒤에도 그대로 유효하다**(DoD 11).

⚠ **주의 3가지**
1. 🔴 **`/sw.js`를 404로 만들지 마라.** 브라우저는 스크립트를 못 받으면 **기존 등록을 유지한다** —
   지우려는 시도가 정확히 반대로 작동한다.
2. 🔴 **`firebase hosting:rollback`은 서비스 워커를 지우지 못한다.** 직전 릴리스의 워커로
   되돌릴 뿐이다.
3. `firebase.json`의 `/sw.js` → `Cache-Control: no-cache`가 이 절차의 전제다. 지우지 마라.

### 1.5 캐시만 비우고 워커는 남기고 싶을 때

`public/sw.js`의 `CACHE` 이름은 **버전 + precache 목록 해시**로 만들어진다.
아무 자산이나 바뀌면 이름이 바뀌고 `activate`가 옛 캐시를 통째로 지운다.
⇒ **손으로 캐시를 비울 일은 없다.** 재배포가 곧 캐시 교체다.

## 3. 🔴 `inviteCodes` 재발급 → 가입 테스트 → 다시 내리기

착수 시점 실측: **`isActive:true` 0건 · `activeInviteCodeId: null`** — 이미 내려져 있다.
체크리스트 8·9번을 하려면 **잠깐 열었다가 다시 닫아야 한다.**

### 3.1 열기 (앱에서 — 콘솔 아님)

1. `head` 또는 `dev` 계정으로 로그인 → **S8 관리**
2. `가입 코드` 섹션 → **`코드 재발급`**(OP-10) → 확인 모달
3. 화면에 뜬 코드를 적어 둔다. `departments.activeInviteCodeId`가 자동으로 갱신된다

⚠ **콘솔에서 손으로 `isActive`를 되돌리지 마라.** `useCount`·`expiresAt`이 과거 값 그대로다.

### 3.2 가입 테스트 (체크리스트 8·9번)

1. 🔴 **창을 전부 닫고** 미가입 학교 계정으로 접속
2. S2에서 동의 체크박스 거동(8번) 확인 후 가입 신청
3. Firebase 콘솔 → Firestore → `users/{새 uid}` →
   **`agreedAt`(타임스탬프) · `agreedPolicyVersion`(`"0.13.0"`)** 존재 확인(9번)

⚠ `agreedPolicyVersion`은 **동의 시점의 앱 버전**이다. 2차 배포 뒤에 가입하면 그 버전이 들어간다.

### 3.3 🔴 다시 내리기 (검증이 끝나는 즉시)

1. Firebase 콘솔 → `departments/dshs-jayul/inviteCodes` → `isActive:true` 문서를 찾는다
2. `isActive` → **`false`**, `revokedAt` → **현재 시각**
3. `departments/dshs-jayul`의 `activeInviteCodeId` → **`null`**
4. 🔴 **문서를 지우지 마라** — `users.inviteCodeId`가 가리킨다(§9.3.1)

**왜**: 공개 URL + 활성 코드 + **App Check 없음 + 레이트 리밋 없음**이 겹친다.
코드 문서 ID가 코드 문자열 자체라 단건 `get`으로 추측을 검증할 수 있다(W-08 안 1).

## 4. 🔴 검증용 2차 배포와 원복 (체크리스트 14~16번)

배너는 **「새 워커가 감지될 때」**만 뜬다. `v0.13.0`을 설치한 기기에 **다른 바이트의 워커**를
한 번 올려야 잴 수 있다. 🔴 **커밋은 `SunDO v0.13.0` 1회 그대로다**(GT-03).

### 4.1 절차

```bash
# ① 정식 배포 (커밋과 같은 상태)
npm run build && npx firebase deploy --only hosting --project sundo-dev-8ef38
#    → 기기에서 설치·실행 (체크리스트 1~13)

# ② 검증용 임시 배포 — sw.js에 주석 한 줄만 더한다
#    🔴 `public/sw.js` 맨 끝에 아래 한 줄을 넣고 저장
#       /* verify-banner */
npm run build && npx firebase deploy --only hosting --project sundo-dev-8ef38
#    → 기기에서 앱을 다시 열면 업데이트 배너 (14) → 탭 (15) → 무시 (16)

# ③ 🔴 원복 — 주석을 지우고 즉시 재배포
git checkout -- public/sw.js
npm run build && npx firebase deploy --only hosting --project sundo-dev-8ef38
git status --short   # ← 비어 있어야 한다
```

⚠ **② ~ ③ 사이에는 저장소와 배포본이 다르다.** 검증이 끝나면 **미루지 말고 ③을 하라.**
⚠ ②에서 `sw.js`만 바뀌므로 `/assets/**` 해시는 그대로다 —
**캐시 이름의 목록 해시도 그대로**라 캐시는 교체되지 않는다. 그것이 정상이다
(바뀐 것이 워커 코드뿐이므로).

### 4.2 되돌리기

③이 실패하면 `npx firebase hosting:rollback --project sundo-dev-8ef38`으로 ①로 되돌린다.
