# W-18 — Firebase 콘솔 확인 요청

> 🔴 **이 회차는 Firestore에 쓰지 않는다.** 규칙 수정 0줄 · 인덱스 0건 · 시딩 0건 · 재배포 0회.
> 아래 **2건은 「데이터 작업」이 아니라 「개인정보 처리방침 문장을 확정하기 위한 확인」**이다.
> 확인 결과에 따라 배포 전에 `src/lib/policy.ts`의 문장이 바뀐다.

## 1. 🔴 Firestore 리전 확인 — 국외 이전 문언이 여기서 갈린다

### 왜 필요한가

개인정보 처리방침 §2에 지금은 이렇게만 적혀 있다.

> 자료는 Google이 운영하는 Firebase에 저장되며 그 범위에서 Google이 처리를 위탁받습니다.

🔴 **저장 위치를 일부러 적지 않았다.** 저장소 어디에도 실제 리전 값의 확인 기록이 없기 때문이다.

| 근거 | 내용 |
| --- | --- |
| `docs/SunDO_PRD.md` §9.1 | 리전 `asia-northeast3` (서울) |
| `database_ToDo/W-04_Firebase_콘솔.md:47` | 「위치: `asia-northeast3` (서울) — 한 번 정하면 바꿀 수 없다」 |
| `src/lib/firebase.ts` 주석 | 「리전은 Firestore를 만들 때 콘솔에서 정한다 — **코드가 아니다**」 |
| 🔴 실제 생성값 | **기록 없음** — `reports/W-04.md`는 지시서를 만들었다고만 적는다 |

**둘은 다른 문장이다** — 「서울로 만들라고 지시했다」와 「서울로 만들어졌다」.
국외 리전이면 **국외 이전 고지가 별도로 필요**하므로 추측으로 적을 수 없다(W-18 결정 1).

### 확인 절차

1. [Firebase 콘솔](https://console.firebase.google.com/) → 프로젝트 **`sundo-dev-8ef38`** 선택
2. 좌측 **빌드 › Firestore Database** 진입
3. 데이터 탭 상단, 컬렉션 목록 위에 **위치 값**이 표시된다
   (예: `asia-northeast3` · `nam5` · `us-central1`)
4. ⚠ 프로덕션 프로젝트를 따로 만들 예정이면 **그쪽 값도 함께** 확인한다(§18.1)

### 결과 기입란

```
Dev  프로젝트 sundo-dev-8ef38  리전: ____________________
Prod 프로젝트 ________________  리전: ____________________   (없으면 「미생성」)
확인일: 2026-__-__
```

### 결과에 따라 할 일

| 결과 | 처리방침 §2 문장 |
| --- | --- |
| **`asia-northeast3`** (또는 다른 국내 리전) | 「Google이 운영하는 국내(서울) 리전의 Firebase에 저장되며」로 **한 문장만** 고친다 |
| 🔴 **국외 리전** | 문장 교체 + **국외 이전 고지 문단을 새로 넣는다**(이전받는 자 · 국가 · 이전 항목 · 이전 목적 · 보유 기간). 🔴 **PM·학교 확인이 먼저다** — 개발이 문안을 정하지 않는다 |

⚠ **리전은 생성 후 변경할 수 없다.** 국외로 만들어졌다면 「고치자」가 아니라
**「고지를 추가할 것인가, 프로젝트를 다시 만들 것인가」**가 결정 대상이 된다.

## 2. 개인정보 보호책임자·문의처 (선택 — PM 제공)

### 왜 필요한가

개인정보 처리방침 §5 `문의처`는 지금 이렇게만 적혀 있다.

> 개인정보 열람·정정·삭제 요청은 자율생활부 담당 교사에게 문의해 주세요.

이것은 design `20i`와 PRD §14.1 PR-03(「학생 본인·학부모는 앱 사용자가 아니다.
열람 요청은 **학교 절차로 처리한다**」)을 그대로 옮긴 것이고, **지금 사실과 어긋나지 않는다.**

다만 학교·교육청 지침이 **책임자 성명·부서·연락처 명시**를 요구할 수 있다.
필요하다면 아래를 PM이 채워 주면 `src/lib/policy.ts`의 §5에 한 문단을 더한다.

```
개인정보 보호책임자 성명 / 직위: ____________________
소속 부서:                      ____________________
연락처(전화 또는 이메일):        ____________________
게시 여부: [ ] 넣는다   [ ] 넣지 않는다(현행 유지)
```

⚠ 🔴 **연락처를 넣는 것 자체가 개인정보 게시다.** 개인 휴대전화가 아니라 **학교 대표 연락처**를
쓸지 PM이 판단한다. 개발이 임의로 채우지 않는다.
