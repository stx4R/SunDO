## 2. 🔴 §2 배포 전 관문 — 전부 통과

W-21C §8 ①(「`firestore.rules`가 배포 직전에 사라질 수 있다」)에 대한 **첫 실전 방어**다.

| # | 관문 | 결과 |
| --- | --- | --- |
| 1 | `git status --porcelain` 깨끗 | ✅ `?? prompts/W-22A.md` **1건뿐**(지시서 자신 · 미추적) |
| 2 | 작업 트리 == `HEAD`의 `firestore.rules` | ✅ blob SHA **양쪽 `c8d64303672c9165734172b8326edc5806b5b3ab`** |
| 3 | 🔴 문자열 `editsDutyOnly` / `assignmentsByMeal` (W-21C) | ✅ `142` · `144` · `434` · `437`행 |
| 4 | 🔴 문자열 `hasOnly(['useCount'])` (W-21B) | ✅ `362`행 |
| 5 | 🔴 `hasOnly` 안의 `activeInviteCodeId` (W-21B) | ✅ `315`행 |
| 6 | `npm run rules:test` | ✅ **231/231** (통과기대 83 · 거부기대 148 · 실패 0) |
| 7 | 🔴 **테스트 뒤** `git diff --numstat firestore.rules` | ✅ **0줄** · SHA 불변 |

🔬 **`git show HEAD:firestore.rules`와의 `diff`가 전 줄 불일치로 나온다 — 이것은 사고가 아니다.**
이 저장소는 `core.autocrlf=true`이고 작업 트리는 **CRLF**, `git show`의 출력은 **LF**다.
`tr -d '\r'`로 정규화하면 **완전 일치**한다.
🔴 **다음 세션이 이것을 사고로 오인하지 않도록, 관문은 `git diff --numstat`과
`git hash-object`(둘 다 정규화된 blob을 본다)로 재는 것이 옳다.**
W-22A §2.1의 `diff firestore.rules /tmp/head.rules`를 **그대로 쓰면 매번 거짓 경보가 난다.**

⇒ 🔴 **규약 4-3·4-4는 이번에 아무것도 빨갛게 만들지 못했다. 그것이 정상 결과다.**
그물은 고기가 안 잡혀도 쳐 두는 것이다.

**17번 절차** — 🔴 실계정에 **차장이 없다**(dev·head·member 셋뿐). 그런데 규칙이

**18번** — 규칙은 `isHead()`이고 **Dev는 부장이 아니다**(W-16D에서 양도했다).
🔴 **판정을 미리 적지 마라.** 보이면 → 누르면 규칙이 막는다(**결함**).
