## 1. 🔴 `sundo.today`에서 Google 로그인 실패 — **원인이 특정됐다**

### 1.1 무엇을 쟀나

지시서 Q-5는 「실제 에러 코드를 물어라」였지만 **물을 필요가 없었다.**
Firebase Auth의 **공개** 설정 엔드포인트(웹 SDK가 매 로드마다 부르는 그것)를 그대로 읽었다.

```bash
curl -s "https://identitytoolkit.googleapis.com/v1/projects?key=<웹 API 키>"
```

```
"authorizedDomains": [ "localhost", "sundo-dev-8ef38.firebaseapp.com", "sundo-dev-8ef38.web.app" ]
```

🔴 **`sundo.today`가 없다.**

⇒ **에러 코드는 `auth/unauthorized-domain`이다.** 팝업이 열렸다 즉시 닫히는 전형적 증상이
그것이고, 지시서 §B-10의 진단표 **②**에 정확히 해당한다.
⚠ 웹 API 키는 비밀이 아니다(브라우저 번들에 그대로 들어 있다). §14.5 12번을 깨지 않았다.

### 1.2 🔴 고치는 법 — **콘솔에서 1분. 코드 수정 0줄.**

1. Firebase 콘솔 → 프로젝트 `sundo-dev-8ef38` → **Authentication** → **설정(Settings)** 탭
2. **승인된 도메인(Authorized domains)** → **도메인 추가**
3. `sundo.today` 입력 → 추가
4. 🔴 **`www.sundo.today`로도 접속할 수 있다면 그것도 함께 추가한다.** 서브도메인은 별개 항목이다.
5. 🔴 **기존 3개를 지우지 마라.** `sundo-dev-8ef38.web.app`은 **`authDomain` 값 자체**이고
   `…firebaseapp.com`은 OAuth 핸들러의 기본 출처다. 지우면 지금 되던 것까지 죽는다.

### 1.3 확인

`https://sundo.today`에서 `Google로 계속하기` → **로그인이 끝까지 진행된다.**
실패하면 브라우저 콘솔의 **에러 코드를 그대로** 적어 다음 세션에 넘겨라 —
`auth/unauthorized-domain`이 아닌 다른 코드면 원인이 ③(OAuth 클라이언트)이나 ④(`authDomain`)다.

## 2. 🔴 `authDomain`은 **아직 바꾸지 마라** — PM 판단이 필요하다

### 2.1 사실

| 무엇 | 지금 값 |
| --- | --- |
| 앱이 서비스되는 출처 | **`https://sundo.today`** |
| `VITE_FIREBASE_AUTH_DOMAIN` | **`sundo-dev-8ef38.web.app`** |
| `sundo.today/__/auth/handler` | **HTTP 200** (커스텀 도메인에서도 예약 경로가 산다 — 전환은 기술적으로 가능하다) |
| `manifest.webmanifest`의 `start_url`·`scope` | `/?source=pwa` · `/` — **출처 상대**라 도메인이 바뀌어도 그대로다(수정 불필요) |

⇒ 🔴 **`.env.example`이 경고한 상태(W-21 P-0)가 실제로 다시 열려 있다** —
「`AUTH_DOMAIN`은 앱이 실제로 서비스되는 출처와 같아야 한다」.
`sundo.today`에서 열면 OAuth가 **교차 출처**가 되어 서드파티 쿠키 정책과
**iOS standalone 무한 루프**의 사정권에 들어간다.

### 2.2 🔴 그런데 지금 바꾸면 안 되는 이유

지시서 §4-5가 「B-10의 원인이 `authDomain` 변경일 때는 멈추고 물어라」로 못 박았다.
**§1의 원인(②)과 이것(④)은 서로 다른 두 사실이고, ①만으로 로그인은 복구된다.**
그리고 `authDomain`을 바꾸면 **아래 셋이 함께 맞아야** 하며, 하나라도 빠지면
지금 되던 브라우저 탭 로그인까지 죽는다.

| 순서 | 무엇 | 어디 |
| --- | --- | --- |
| ① | §1의 승인 도메인 추가 | Firebase 콘솔 |
| ② | **승인된 JavaScript 원본**에 `https://sundo.today` | Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보 → OAuth 2.0 클라이언트 ID |
| ③ | **승인된 리디렉션 URI**에 `https://sundo.today/__/auth/handler` | 같은 화면 |
| ④ | `.env.local`의 `VITE_FIREBASE_AUTH_DOMAIN=sundo.today` → **재빌드 · 재배포** | 저장소 |

🔴 **옛 도메인(`sundo-dev-8ef38.web.app`)의 항목은 어느 것도 지우지 마라.**
롤백 대상 릴리스가 그 값으로 빌드돼 있다 — 지우는 순간 롤백이 불가능해진다.

**⇒ PM 결정 사항**: ①만 하고 멈출 것인가, ①~④를 한 번에 갈 것인가.
후자를 고르면 **되돌리기 절차**(`.env.local`을 되돌리고 재배포)를 먼저 적어 두고 시작하라.
