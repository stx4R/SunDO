# W-03C 보고서 — Toast · BottomSheet · ConfirmModal

작업 지시서: `prompts/W-03C.md`
버전: **SunDO v0.0.5**

W-03 3분할이 여기서 끝난다. 공통 컴포넌트 14종의 최종 API는 §8에 있다.

> **§1이 지정한 `fs.rmSync` 한 줄은 이 환경에서 그대로 쓸 수 없었다.** 크래시의 원인이
> OneDrive가 아니라 **Node v24.2.0의 `fs.rmSync` 자체**였기 때문이다(§4-1).
> 같은 목적을 같은 방식(의존성 0개, `node -e`)으로 달성하는 비동기 API로 바꿨고,
> DoD 1(`dist/`가 있는 상태에서 연속 2회 통과)은 충족한다.

## 4. 판단이 필요했던 지점

### 4-1. 빌드 크래시의 원인은 OneDrive가 아니라 `fs.rmSync`였다 (W-03B 진단 정정)

§1이 지정한 한 줄을 그대로 넣고 실행했더니 **같은 크래시가 났다.** 원인을 다시 갈랐다.

| 시도 | 결과 |
| --- | --- |
| `node -e "fs.rmSync('dist',{recursive:true,force:true})"` | **exit 127**, 삭제 안 됨. PowerShell에서는 `-1073740791`(`0xC0000409`) |
| `node -e "fs.rmSync('a.txt')"` — 파일 1개 | **exit 127**, 삭제 안 됨 |
| `node -e "fs.unlinkSync('a.txt')"` | ✅ 정상 |
| `node -e "fs.promises.rm('dir',{recursive:true,force:true})"` | ✅ 정상 |
| 셸 `rm -rf dist` (coreutils) | ✅ 정상 |
| OneDrive **밖** 임시 폴더에서 `rmSync` | **exit 127** — 폴더 위치와 무관 |

**`fs.rmSync`만 죽는다.** 재귀도 아니고 파일 하나여도 죽는다. Node **v24.2.0** / Windows 11.
vite의 `emptyOutDir`가 이 API를 쓰기 때문에 `dist/`가 있으면 빌드가 통째로 죽었던 것이다.
W-03B 보고서 §8-1이 OneDrive를 지목한 것은 **오진이었다.** 그때는 `rm -rf`(별도 실행 파일)로
우회해서 Node 안쪽이 문제라는 신호를 못 봤다.

→ 같은 목적·같은 제약(의존성 0개, `node -e`, `cmd.exe` 호환)을 지키면서 API만 비동기로 바꿨다.

```json
"build": "node -e \"require('fs').promises.rm('dist',{recursive:true,force:true})\" && tsc -b && vite build"
```

`dist/`가 있는 상태에서 연속 2회 실행 → 둘 다 exit 0. **§1의 의도(옛 번들 실측 방지)는 그대로 달성된다.**
지시서의 문자열을 바꾼 것이라 §7-1에 확인 요청으로 남긴다.

### 4-2. 오버레이 루트를 스크롤 영역의 **형제**로 뒀다

스크롤 영역 안에 넣으면 시트가 본문과 함께 스크롤되고, 딤도 스크롤 높이(3840px)만큼 늘어난다.
스테이지 직계 자식으로 두면 스테이지 높이에 고정되고 딤이 스크롤 영역 전체를 정확히 덮는다.
DoD 17(배경 스크롤 차단)이 이 배치라야 별도 코드 없이 성립한다 — 실측에서 `scrollTop`이
움직이지 않은 이유는 **딤이 형제라 휠 이벤트가 스크롤 영역으로 전달되지 않기 때문**이다.
`overflow: hidden`을 추가로 걸 필요가 없었다.

루트 자체는 `z-index`를 주지 않았다. 주면 새 쌓임 맥락이 생겨 자식의 40~60이 독(30)과
같은 층에서 겨루지 못한다. `position: absolute` + `z-index: auto`는 쌓임 맥락을 만들지 않는다.

### 4-3. 포커스 트랩은 **마운트 이후**에 걸어야 한다 (실측에서 잡은 결함)

처음에는 `useFocusTrap({ open })`으로 걸었다. 실측에서 **포커스가 시트로 들어가지 않았고
ESC도 듣지 않았다.** `open`이 true가 되는 렌더에는 아직 시트가 마운트 전이라 `ref.current`가
`null`이고, 훅이 조기 반환한 뒤로는 의존성(`open`)이 변하지 않아 다시 돌지 않는다.

→ `open && mounted`를 넘긴다. 마운트가 끝난 렌더에서 효과가 처음 돌아 포커스·키 리스너가 붙는다.
수정 후 실측: 포커스 진입 ✅ · Tab 순환 ✅ · ESC ✅ · 트리거 복귀 ✅.

### 4-4. 닫힘 모션을 위해 언마운트를 늦추는 훅을 공유로 뺐다

`open`이 false가 되는 즉시 언마운트하면 닫힘 모션이 보이지 않는다. 시각 상태를 먼저 끄고
전환 시간만큼 기다렸다 DOM에서 뺀다. 시트(380ms)·모달(250ms) 둘 다 필요하므로
`src/lib/useOverlayTransition.ts`로 공유했다(§3 기준: 2개 이상에서 쓰인다).
reduce에서는 CSS 지속시간이 0.01s로 줄어드니 대기도 10ms로 줄인다.

### 4-5. 시트 모션은 design(`sheetUp`)이 아니라 지시서(`translateY(110%)`)를 따랐다

design `17a` 원문은 `sheetUp .38s`(`translateY(55%)` + `opacity .4 → 1`)다.
지시서 §5.1과 DoD 14는 `translateY(110%) ↔ 0`이다. **지시서를 따랐다.**
110%는 시트가 화면 밖에 완전히 나가 있는 상태이고, 55% + 페이드는 "반쯤 보이다 선명해지는"
다른 연출이다. 지속·이징(`0.38s`, `cubic-bezier(.2,.8,.25,1)`)은 양쪽이 같다.
또 키프레임 대신 `transition`으로 낸 이유는 닫힘에도 같은 값을 되감아야 하기 때문이다(딤·모달도 동일).

### 4-6. 시트 내부 하이라이트는 `--highlight-top`(0.85)이라 design(0.9)과 0.05 다르다

design `17a` 시트의 원문은 `inset 0 1px 0 rgba(255,255,255,0.9)`이고 테두리도 `0.9`다.
지시서 §5.1이 내부 하이라이트를 `--highlight-top`(= `0.85`)으로 지정했고 §2.1이 시트를
세 번째 사용처로 명시했으므로 **토큰을 썼다.** 테두리는 원문대로 `0.9`로 두었다.
1px 흰 선의 알파 0.05 차이라 육안으로는 구분되지 않지만, 원문과 다른 값이라 여기에 남긴다.
되돌리려면 `.sheet`의 `var(--highlight-top)`을 리터럴로 바꾸면 된다(1줄).

### 4-7. §6.2가 지시한 신규 확정 2건 — 그대로 구현했다

1. **초기 포커스는 좌측 `취소`.** 파괴적 버튼에 두면 Enter 오조작이 난다. 7종 전부 실측 확인.
2. **딤 탭·ESC = `취소`.** 닫을 방법이 버튼뿐이면 키보드 사용자가 갇힌다(AC-09).
   `취소`가 비파괴적 기본값이라 안전하다. 카운터 실측으로 `onConfirm`이 절대 불리지 않음을 확인.

여기에 더해 **`loading`으로 두 버튼이 모두 비활성일 때**를 실측하다 구멍을 찾았다.
비활성 버튼에 `focus()`는 아무 일도 하지 않아 포커스가 트리거(모달 밖)에 남는다.
→ 훅이 포커스 결과를 확인하고 컨테이너(`tabindex="-1"`)로 되돌리게 했다. 실측 `activeElement`가
모달 카드가 된다. 트랩 밖으로 새지 않는다.

### 4-8. 모달 버튼은 `Pill`을 쓰지 않고 `.mbtn` 계열로 만들었다

지시서 §6.1 지시대로다. 근거도 실물로 확인했다 — `.pill`은 `radius 999` · `padding 7px 13px`,
모달 버튼은 `height 48` · `radius 14` · `flex: 1`이라 표면이 다르다.
로딩 스피너는 `.btnp-spin`(18px 흰색)을 그대로 재사용했다. `spin` 키프레임은 이제 3곳이 공유한다.

### 4-9. 토스트 진입 모션 `toastIn`을 새로 썼다

design `10e`의 토스트는 `animation: blurIn .35s ease both`인데 `blurIn`은 §10에서
**W-05 범위로 제외**됐다. 지시서 §4.1이 지정한 값은 "진입 `0.3s ease`"다.
→ 원문과 같은 방향·거리(`translateY(10px) → 0`)를 유지하고 `filter: blur(8px)`만 뺀
`toastIn`을 `0.3s ease`로 새로 썼다. `translateX(-50%)`는 위치라 키프레임이 계속 들고 있어야 한다
(빼면 애니메이션이 도는 동안 토스트가 오른쪽으로 밀린다).

### 4-10. 토스트 교체는 큐가 아니라 `key` 교체다

§6.4는 "동시 1개, 신규 발생 시 기존 즉시 교체"다. 큐를 만들지 않았고, 교체마다 증가하는
`seq`를 `key`로 준다. 같은 문구가 연속으로 와도 React가 노드를 새로 만들어 진입 모션이 다시 돈다
(DoD 11). 타이머는 교체 시 초기화되므로 마지막 토스트 기준으로 2.2초다.

## 7. 사용자 확인이 필요한 사항

1. **§1의 지정 문자열을 바꿨다**(§4-1). `fs.rmSync`가 이 Node(v24.2.0/Windows)에서 프로세스째
   죽어서 `fs.promises.rm`으로 갔다. 의존성·실행 방식·의도는 그대로다.
   - 되돌리기 비용: `package.json` 1줄. 단 되돌리면 빌드가 다시 죽는다.
   - **W-03B 보고서 §8-1의 "OneDrive 원인" 진단은 오진이었다.** PRD/보고서에 반영이 필요하면 알려달라.
   - 근본 대응(선택): Node LTS(22.x)로 내리면 `rmSync`가 정상 동작할 가능성이 높다. 확인해 볼지.
2. **시트 내부 하이라이트가 design보다 알파 0.05 낮다**(§4-6). 지시서 §5.1·§2.1을 따른 결과다.
   원문(0.9)으로 되돌리려면 `.sheet` 1줄만 바꾸면 된다.
3. **시트 모션이 design `sheetUp`과 다르다**(§4-5). 지시서·DoD 14가 `translateY(110%)`를
   명시해 그쪽을 따랐다. design 연출(55% + 페이드)로 갈지 정해달라.
4. **토스트에 수동 닫기 수단이 없다.** §6.4 규격대로 2.2초 자동 소멸만 있다. AC-10이
   "토스트에만 의존해 중요한 정보를 전달하지 말라"고 하므로 현행이 규격 위반은 아니다.
   다만 스크린리더 사용자가 낭독 도중 사라질 수 있다 — W-18 접근성 점검 항목으로 넘긴다.
5. **`ToastProvider`의 위치.** 지금은 스토리 페이지가 `AppShell` 안쪽에서 감싼다. W-05에서
   라우터가 들어오면 **모든 화면이 공유하도록 라우트 루트에 한 번만** 두어야 한다.
   화면마다 Provider를 두면 화면 전환 시 토스트가 사라진다.
