## 4. 판단과 이탈

### 4-1. 🔴 강등 대상을 **`departments.headUid`**로 잡았다 — 두 경로가 한 형태가 된다

R-02·BR-19의 문언은 「대상 → `head`, **본인** → `member`」다. 그런데 §4.1이 Dev에게 전 기능 접근을 주고
결정 2가 **Dev도 양도할 수 있다**로 확정했으므로, Dev 경로에서 「본인 → member」는 **거짓**이 된다
(Dev의 role은 바뀌지 않는다).

→ **강등 대상을 `departments/{id}.headUid`가 가리키는 사람으로 잡았다.** 그러면

- `head` 실행: `headUid == 본인`이므로 결과가 R-02의 문언과 같다
- `dev` 실행: `headUid == 현 부장(남)`이므로 부장이 강등되고 Dev는 그대로다

**한 코드 경로가 두 경우를 모두 낸다.** 실측 — head 실행 `oldHead: uid-head` 강등, dev 실행도 `uid-head` 강등.
🔴 **본인 uid로 잡았다면 Dev 경로에서 강등 연산이 아예 빠져 부장이 2명이 됐을 것이다.**
→ §7 신규 항목(R-02·BR-19 문언 수정).

### 4-2. 🔴 **성공 직후 「접근 권한이 없습니다」가 실제로 떴다 — 세 번 실패한 뒤 잡았다**

지시서 §3.6이 「토스트 → `navigate` → `refresh()`」 순서를 지시하고 「`refresh()`를 먼저 부르면 TS-12로
덮인다」고 경고했다. **그 순서를 그대로 지켰는데도 TS-12가 떴다.**

실측 trace(고치기 전):

```
replaceState:/ from=/admin        ← navigate('/', {replace:true})
refresh:auth.currentUser          ← refresh() 진입
RequireRole render denied=true role=member path=/     ← 🔴 여기
replaceState:/ from=/             ← RequireRole의 <Navigate>
toast:부장 권한을 양도했습니다
toast:접근 권한이 없습니다         ← TS-09를 덮는다
```

**원인** — `navigate`의 라우터 상태 갱신은 `startTransition`이라 **커밋이 미뤄진다.**
그 사이 `refresh()`가 `profile.role`을 `member`로 바꾸면, 그 **동기 갱신이 전환을 앞질러**
아직 커밋돼 있는 `/admin` 트리를 다시 그린다. 그 렌더에서 `RequireRole`이 `denied`가 되고,
토스트는 큐가 없어(W-03C §4-10) TS-09가 TS-12로 즉시 교체된다.

**시도하고 실패한 것 3가지** — 전부 실측으로 확인했다:

| 시도 | 결과 |
| --- | --- |
| `navigate(...)` 뒤에 `refresh()` (지시서 §3.6 그대로) | ❌ TS-12 |
| 바깥을 `ReactDOM.flushSync(() => navigate(...))`로 감싸기 | ❌ TS-12 — 전환은 동기 flush 대상이 아니다 |
| `await navigate('/', { replace: true, flushSync: true })` | ❌ TS-12 — `flushSync` 옵션은 **최종** 상태 갱신에만 걸리고 `navigate`의 promise는 커밋을 기다리지 않는다 |

→ **채택** — 「이동 뒤」가 아니라 **「이 화면이 실제로 사라진 뒤」**에 갱신한다.

```tsx
const refreshOnUnmountRef = useRef(false)
useEffect(() => () => { if (refreshOnUnmountRef.current) void refresh() }, [refresh])
// 성공 시:  refreshOnUnmountRef.current = true;  navigate('/', { replace: true })
```

언마운트 정리 함수는 `RequireRole`이 트리에서 **사라진 뒤**에 돈다. TS-12가 뜰 창 자체가 없다.
실측(고친 뒤): `replaceState:/` → `toast:부장 권한을 양도했습니다` → `refresh:auth.currentUser`,
최종 토스트 **1개**, 독 탭 `[홈, 기록, 일정, 설정]`.

⚠ **`refresh()`가 실패해도 재시도하지 않는다**(PROGRESS 확정 — `status`·`profile`을 흔들지 않는다).
갱신이 실패하면 독에 `관리`가 남지만, 눌러도 `RequireRole`이 정상적으로 TS-12로 막는다.

🔴 **이것을 §9-3(「막을 수 없으면 물어라」)로 올리지 않은 이유** — 막을 수 있었기 때문이다.
「이동 먼저, 갱신 나중」이라는 지시의 **의도**는 그대로 지켰고, 관측 가능한 경계를 「이동 완료」에서
「언마운트」로 옮겼을 뿐이다.

### 4-3. 🔴 클라이언트 배치는 「부장 1명」을 보장하지 못한다 — 규칙 회차로 넘겼다

네 연산은 원자적이다(실측 — 3번째에 실패 주입 → 쓰기 0건, 네 문서 원복). 커밋 전에 대상(BR-20)과
현 부장을 `getDoc`으로 확인한다. **그러나 확인과 커밋 사이의 창은 닫을 수 없다** — 같은 순간
다른 부장·Dev가 다른 사람에게 양도하면 결과가 부장 2명이 될 수 있다.

실질 보장자는 Rules(§9.6 필수 조건 3)와 BR-23의 Dev 복구 경로다.
🔴 `database_ToDo/W-15B.md` §4가 **규칙이 판단해야 할 3가지**로 정리했다 — 특히
「`headUid`를 단일 진실로 삼고 `users.role=='head'`를 그 파생으로 강제할 것인가」.

### 4-4. 🔴 현 부장 문서가 없으면 **강등만 빼고 승격 3연산으로 성공**한다

`batch.update`는 대상 문서가 없으면 배치 전체를 실패시킨다(W-15A §4-2). 그래서 현 부장 문서를
미리 `getDoc`하고, **없거나 `role !== 'head'`면 그 연산만 뺀다.**

🔴 **그 상태가 곧 BR-23이 말하는 「부장 0명」 사고 상태다.** 거기서 양도가 막히면 복구할 방법이 사라진다.
실측 — 문서 삭제 시 3연산 성공, `role='member'`로 바꿔도 3연산 성공. 감사 로그의 `before`는 `{headUid: null}` 또는
`{headUid: '<가리키던 uid>'}`로 **사실 그대로** 남는다.

⚠ 반대로 **읽기 실패는 「강등 대상 없음」으로 읽지 않는다** — 그렇게 하면 부장이 2명이 된다.
`getDoc`이 throw하면 배치를 시작하지 않고 실패를 돌려준다(오프라인이면 어차피 커밋도 resolve되지 않는다).

### 4-5. `clearAdminCache()`를 **넓혔다** — 여섯 번째를 만들지 않았다

부원 목록 캐시(`memberCache`)가 생겼지만 `clearMemberCache`를 만들지 않고 기존 함수가 둘 다 비운다.

🔴 **`clearHomeCache()`를 부르지 않았다.** `stats.ts`의 `deptCache`는 `academicYear`·`classCountByGrade`만
담고 **`headUid`를 담지 않는다** — 지시서가 「부르지 마라」고 한 이유보다 더 강한 근거가 코드에 있었다.

토큰(`0.875rem`)은 나머지 스케일과 함께 커진다. `@theme` 주석이 규정한 「AC-05: rem 기반,

### 4-9. 보정 ③ — 스태거를 **규칙으로 계산한다**

## 6. 검증 환경

- **스텁 하네스** — W-15A와 같은 방식. 임시 별칭 **5개**(`firebase/app`·`firebase/auth`·

  스텁 `auth`에 getter를 두고 흔적을 남겼다. `history.replaceState` 패치와 토스트 `MutationObserver`를 합쳐
