## 4. 판단이 필요했던 지점과 근거

### 4.1 `@keyframes shine`이 프로토타입에서 고아 상태였다

`design/index.html`에 `@keyframes shine`이 **정의만 되고 적용 규칙이 0건**이었다. 근거:

| 검사 | 결과 |
| --- | --- |
| `animation:shine` | **0건** |
| `background-size` | **0건** |
| `background-clip` | **0건** |
| `"2.8s"` | **0건** |
| `@keyframes shine` | 1건 (정의만) |

`background-size`가 없으면 `background-position` 애니메이션은 시각적으로 아무 일도 하지 않는다.
즉 프로토타입에서 `.shine`은 한 번도 동작한 적이 없고, **이식할 원본이 존재하지 않았다.**
지시서 §2.0("거기에도 없으면 지어내지 말고 질문한다")에 따라 코드를 쓰기 전에 멈추고 질문했다.

회신 §1.2로 적용 규칙을 신규 확정했다. 전문은 아래 §5.2에 있다.

### 4.2 `.fchip-on` — PRD(단색)를 채택하지 않고 design(그라디언트)을 채택

| 출처 | 규격 |
| --- | --- |
| PRD §7.3 | 활성 시 **단색 `#1F5138`** 배경 + 흰 글자 |
| 지시서 원본 §3 | 배경 `--color-sundo-800` + 흰 글자 + 700 |
| `design/index.html` | **`linear-gradient(160deg,#2E6B4C,#1F5138)`** + `box-shadow: 0 6px 16px rgba(31,81,56,0.28)` + 12px/700 흰 글자 |

CLAUDE.md "디자인과 PRD가 충돌하면 코드를 쓰지 말고 먼저 보고한다"에 따라 질문했고,
회신 §2.1로 **design 채택**이 확정됐다. 근거는 (1) PRD §20.1상 시각 원본은 Claude Design 산출물,
(2) 활성/채움 표면이 전부 `--gradient-primary`인 시스템 정합성, (3) 그라디언트 끝 색이 `#1F5138`이므로
PRD 표기가 그라디언트를 한 색으로 줄여 적은 전사 오류로 보는 편이 자연스럽다는 것이다.

배경은 `--gradient-primary` 토큰으로 치환했고, 그림자는 `--shadow-primary`(`0 10px 24px rgba(31,81,56,0.35)`)와
**값이 달라** 회신 §2.1 지시대로 토큰화하지 않고 design 원문을 인라인으로 두었다.

### 4.3 `.pill` 3종은 design에 없어 PRD + 공통 프롬프트로 확정

`design/index.html`에 `.pill` 규격(`padding 7px 13px`, 11.5px/700)이 **아예 없었다.**
회신 §3으로 확정: `pill-soft`는 `tint-10`, `pill-line`은 `.tage`와 동일한 표면 처리.

`tint-10` 근거로 제출한 사용 빈도 — `rgba(31,81,56,0.10)` **156회** / `0.08` 33회 / `0.12` 2회.
`.chip`·`.tagl`도 전부 `tint-10`이다.

### 4.4 `tailwind-merge` 충돌이 실제로 발생했다 — 쇼케이스 호출부만 수정

지시서 §4가 "실제로 나오면 그때 W-03에서 붙인다"고 한 리스크가 **이번 작업에서 곧바로 재현됐다.**

```
twMerge('text-h1', 'text-sundo-900')                  ->  'text-sundo-900'          ← text-h1 소실
twMerge('text-label', 'font-bold', 'text-sundo-ink-70') ->  'font-bold text-sundo-ink-70'  ← text-label 소실
twMerge('rounded-11', 'p-4')                          ->  'rounded-11 p-4'          ← 정상
```

원인: `tailwind-merge` 기본 설정은 자체 내장 스케일만 안다. `text-h1`이 글꼴 크기인지,
`text-sundo-900`이 색인지 판별하지 못해 **둘을 같은 `text-*` 그룹으로 보고 뒤엣것만 남긴다.**
쇼케이스 초기 버전에서 글꼴 크기 13종이 전부 16px로 렌더된 것이 이 때문이었다.

토큰 레이어는 정상이다 — `.text-h1{font-size:var(--text-h1);letter-spacing:var(--tw-tracking,var(--text-h1--letter-spacing))}`
가 정상 생성돼 있고, 클래스를 직접 주면 28px로 렌더된다.

지시서 §4가 `extendTailwindMerge` 설정을 **금지**했으므로 설정은 건드리지 않고,
충돌이 나는 쇼케이스 호출부만 `cn()` 대신 문자열 결합으로 바꾸고 주석을 남겼다.
→ **§6-1 사용자 확인 필요**

### 4.5 `.neu` 내부 링은 토큰화하지 않았다

`.neu`의 내부 링 `inset 0 0 0 1px rgba(255,255,255,0.6)`은 값이 `--color-sundo-control`과 같지만
**배경이 아니라 그림자 색**이다. `control`은 컨트롤 표면용 배경 토큰(`.fchip` 비활성, 독 배경 등)이므로
그림자 색으로 재사용하면 의미가 어긋나고, 나중에 한쪽 값만 바꿔야 할 때 함께 끌려간다.
회신 §2.2의 "1회뿐이면 인라인" 규칙을 적용해 인라인으로 두었다. → §5.1 목록에 기재.

### 4.6 검증 중 겪은 계측 오차 2건 (결과에는 영향 없음)

- **탭 스로틀링** — Chrome 백그라운드 탭에서 CSS 전이·애니메이션이 진행되지 않아
  `.shine`이 멈춘 것처럼, `:active` scale이 `1`인 것처럼 보였다. `playState`는 `running`이었다.
  애니메이션 `currentTime`을 직접 지정하고 전이를 `none`으로 끈 뒤 측정해 해결했다.
- **Lightning CSS 정규화** — 빌드 CSS에서 `rgba(255,255,255,0.55)`가 `#ffffff8c`로,
  `0.9375rem`이 `.9375rem`으로 축약된다. 값은 동일하다(알파 0.55×255=140=0x8C).
  대조 스크립트에 정규화를 넣어 처리했다. 브라우저 computed 값은 다시 `rgba()` 형태로 돌아온다.

### 5.2 W-02에서 신규 확정한 것 — `.shine` 적용 규칙

프로토타입에 존재하지 않아 회신 §1.2로 확정했다. **PRD §7.3에 규격이 없던 부분이다.**

```css
.shine {
  display: inline-block;
  background-image: linear-gradient(100deg,
    rgba(255,255,255,0)    40%,
    rgba(255,255,255,0.45) 50%,
    rgba(255,255,255,0)    60%);
  background-size: 200% 100%;
  background-repeat: no-repeat;
  animation: shine 2.8s linear infinite;   /* 2.8s linear infinite = PRD §7.4 */
}
```

- `100deg`와 정지점 3개(40% / 50% / 60%), `rgba(255,255,255,0.45)`, `background-size: 200% 100%`가 신규 값이다.
- `background-clip: text`는 쓰지 않았다. 라벨이 이미 흰색 16/700이라 텍스트 클리핑으로는 더 밝아질 수 없고,
  design 파일에도 `background-clip`이 0건이다.
- `2.8s linear infinite`는 PRD §7.4에 있어 신규 값이 아니다.
- 좌→우 이동을 실측으로 확인했다(§3 DoD #16).

### 5.3 토큰화하지 않고 인라인으로 남긴 리터럴

회신 §2.2 규칙("11종 안에서 2회 이상 반복되면 토큰화, 1회뿐이면 인라인 + 보고")을 적용했다.

| --- | --- | --- | --- |
| `rgba(255,255,255,0.85)` | `.glass` box-shadow | design 통계 카드 인라인 style | 11종 중 1회 |
| `rgba(255,255,255,0.6)` | `.neu` / `.neu:active` box-shadow | design 학년 버튼 인라인 style | 배경이 아닌 **그림자 색**이라 `--color-sundo-control`로 치환하면 의미가 어긋남 (§4.5) |

## 6. 사용자 확인이 필요한 사항

### 6-1. `tailwind-merge` 커스텀 스케일 충돌 — **리스크가 아니라 확인된 결함**

지시서 §4가 "리스크로 남기라"고 한 항목이 **이미 재현됐다**(§4.4). 현재 상태에서
`cn('text-h1', 'text-sundo-900')`처럼 **커스텀 글꼴 크기와 커스텀 색을 함께 넘기면 글꼴 크기가 조용히 사라진다.**
에러도 경고도 없이 16px로 렌더되므로 눈으로 잡기 전까지 드러나지 않는다.

영향 범위: `text-h1` `text-h2` `text-sheet` `text-grade` `text-classno` `text-stat` `text-body`
`text-button` `text-row` `text-label` `text-caption` `text-micro` `text-dock` — **13종 전부.**
`rounded-*`는 충돌하지 않는다(확인함).

W-03에서 `Field`·`Button` 등 컴포넌트가 `cn()`으로 className을 받기 시작하면 곧바로 터진다.
지시서 §4의 금지 지시를 지켜 이번에는 손대지 않았으나, **W-03 착수 시점에
`extendTailwindMerge`로 커스텀 스케일을 등록할 것을 권한다.** 등록할 내용은 아래와 같다.

```ts
// W-03에서 적용할 것 (W-02에서는 지시서 §4에 따라 미적용)
extendTailwindMerge({
  extend: {
    classGroups: {
      'font-size': [{ text: ['h1','h2','sheet','grade','classno','stat','body',
                             'button','row','label','caption','micro','dock'] }],
      rounded: [{ rounded: ['pill','28','26','24','22','20','18','16','15','14','12','11'] }],
    },
  },
})
```

### 6-2. `index.html` 누락 2건 (§8에 따라 고치지 않음)

| 항목 | PRD | 현재 `index.html` |
| --- | --- | --- |
| `viewport-fit=cover` | §7.5 | **없음** (`width=device-width, initial-scale=1.0`만) |
| `theme-color: #F7FBF8` | §7.1 `--bg-top` 용도, §7.5 | **`<meta name="theme-color">` 자체가 없음** |

지시서 §8이 "확인만 하고 고치지 말라"고 해서 그대로 두었다. safe-area 패딩을 다루는
W-03 `AppShell` 작업에서 함께 넣는 것이 자연스럽다.

### 6-3. §7.1 보완 토큰 5개 — PRD v1.3 반영 대상

전부 값을 새로 만든 것이 아니라, PRD 본문·Claude Design 산출물에서 이미 반복 사용 중인 리터럴을 승격한 것이다.

### 6-4. `.pill-fill` 그림자 없음 — 확인 요청

회신 §3이 `.pill-fill`에 "그림자 없음"을 명시해 그대로 따랐다. 다만 같은 `--gradient-primary`를 쓰는

평평하다. 의도된 차이라면 그대로 두면 되고, 아니라면 W-03에서 값을 정해달라.
