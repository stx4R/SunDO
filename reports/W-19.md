### 2.2 SPA rewrite · 캐시 헤더

| 경로 | 상태 | Cache-Control |
| --- | --- | --- |
| `/` | 200 · `index.html` | `no-cache` |
| `/policy/privacy` · `/policy/terms` · `/policy/oss` | 200 · **직접 진입 정상** | `no-cache` |
| `/settings` · `/grade/1/class/3` | 200(리라이트) | `no-cache` |
| `/assets/index-*.css` · `.js` | 200 | `public, max-age=31536000, immutable` |
| `/fonts/*.woff2` | 200 | `public, max-age=31536000, immutable` |
| `/sw.js` · `/manifest.webmanifest` | 200 | `no-cache` |

🔴 **처음에는 `/`가 `max-age=3600`이었다.** `headers.source`가 **리라이트 결과가 아니라 요청
경로**에 매칭되기 때문에 `"/index.html"` 규칙이 `/`·`/policy/*`에 닿지 않았다. `**` 규칙을
**가장 뒤에** 두어 닫았다 — 그리고 그 과정에서 Firebase Hosting의 헤더 매칭이
**first-match wins**임을 실측했다(`/assets/**`가 뒤의 `**`에 덮이지 않았다).

⚠ **측정 함정 — 배포 직후에 헤더를 재면 직전 배포의 엣지 캐시를 잰다.** 고친 뒤에도
`/`는 한동안 `max-age=3600`으로 나왔고, `?bust=1`을 붙이자 `no-cache`가 나왔다.
**쿼리스트링으로 가르지 않으면 「고쳤는데 안 고쳐졌다」는 오진을 한다.**

### 2.3 COOP (§3.7-4 · W-16D §13)

```

```

갱신은 서버가 내주는 `sw.js`의 `VERSION`을 `0.12.0` → `0.12.1`로 바꿔 일으켰다.

### 3.2 🔴 §18.2와 §3.3-3이 충돌하는 지점, 그리고 고른 것

- §18.2: 「새 SW 감지 시 **하단 배너** 노출, **탭 시** `skipWaiting` 후 리로드」 = **대기시킨다**
- 지시서 §3.3-3: 「`skipWaiting` + `clients.claim()`으로 **즉시 활성화**」

**둘 다 지켰다.** `install`에서 `skipWaiting()`을 자동으로 부르지 **않아** 대기 상태를 만들고
(§18.2), 그 대기를 푸는 **경로를 확보**한다(§3.3-3의 본문 — 「경로를 확보한다」이지
「자동으로 넘긴다」가 아니다). `clients.claim()`은 `activate`에 그대로 있다.

🔴 **남는 위험을 숨기지 않는다** — 사용자가 배너를 무시하면 낡은 워커가 남는다.
지금은 **워커가 아무것도 캐시하지 않아 콘텐츠가 네트워크에서 오므로 증상이 없다.**
**W-20이 캐시를 붙이는 순간 이 문장이 거짓이 된다.** §8-2에 전제로 넘긴다.

## 4. 판단과 이탈

### 4.1 아이콘 — 의존성 0으로 만든 방법

🔴 **헤드리스 Chrome의 `canvas`에 그려 뽑았다.** 스크린샷이 아니다 — 스크린샷은 뷰포트·DPR이
개입해 「512를 요청했는데 512가 아닌 것」이 나온다. `canvas.width = 512` + `toDataURL()`은
그 변수를 없앤다. 도구 추가 **0개**, `sharp`·`jimp`·`pwa-asset-generator` **0개**.

| 파일 | 크기 | 로고 | 배경 |
| --- | --- | --- | --- |
| `icon-192.png` | 192 | 169px (88%) | `#F7FBF8` |
| `icon-512.png` | 512 | 451px (88%) | `#F7FBF8` |
| `icon-512-maskable.png` | 512 | **338px (66%)** | `#F7FBF8` full-bleed |
| `apple-touch-icon-180.png` | 180 | 158px (88%) | `#F7FBF8` |

- **maskable 안전 영역**: 중앙 80% = 지름 409.6px. 로고가 **338px**이라 **사방 36px 여유**.
  원형 엠블럼이라 마스크가 원이든 스퀘어클이든 잘리지 않는다. 눈으로도 확인했다.
- **배경을 불투명하게 깐 이유**: `apple-touch-icon`은 투명을 지원하지 않아 iOS가 검게 칠한다.
  값은 §7.1 `--bg-top`이고 manifest `background_color`와 같은 값이라 **새 색이 아니다.**
- ⚠ **512는 원본(390px)보다 크다** — 1.15배 확대다. 원본이 그것뿐이었고, 눈으로 확인했을 때
  원형 테두리·`DSHS` 자획이 깨지지 않는다.

🔴 **출처 판단**: 착수 시점의 `DSHS.png`는 **학교 교표**였고 지시서 §9-4가 「저작권·승인 문제다.
배포하지 마라」로 규정해 **멈추고 물었다.** 사용자가 「쓴다」로 답하며 파일을
**「대신 학생자치회」 엠블럼**으로 교체했다. **소속 학생자치회의 부서 앱**이라는 관계가
교표와 다르다는 점을 사용자가 판단한 것으로 본다. 🔴 **학교/자치회의 사용 승인 여부는
여전히 개발이 확인할 수 없다** — §7 st4R에 남긴다.

### 4.2 글꼴 — 왜 5개를 다 선언했나

앱이 쓰는 굵기는 **400·500·700**뿐이다(600·800은 파일이 없어 오늘도 700으로 매칭된다).
그런데 `@font-face`는 **5개** 선언했다. CDN CSS와 **1:1**이기 때문이다 —
줄이는 순간 「오늘과 같은 파일, 같은 동작」이라는 주장이 거짓이 된다.
**브라우저는 실제로 쓰이는 face만 받으므로 전송량 비용이 0이다**(§2.5 `unloaded` 실측).

**`font-display: swap`** — ① CDN CSS가 쓰던 값이라 전환으로 바뀌는 것이 없다
② `block`·`optional`과 달리 **글자가 보이지 않는 구간을 만들지 않는다**(§15 접근성).
**`local()`을 남긴 것**도 CDN CSS 원문 그대로다.

### 4.3 배너 2종 — design 좌표를 그대로 쓰지 않은 이유

design `10c`·`10d`는 `bottom:132px`이고 같은 시안의 독은 `bottom:50px`이다.
