## 4. 판단과 이탈

### 4.1 🔴 **최고 산출 — 삽입 앵커가 어느 블록의 닫는 괄호인지 확인하지 않았다**

`.set-*` **402줄 전체가 `@media (max-width: 380px)` 안에 들어갔다.**
아이폰 폭(390~430px)에서는 한 줄도 적용되지 않아 S10 레이아웃이 통째로 깨졌다.

**어떻게 일어났나** — `src/index.css` 끝에 CSS를 붙이면서 앵커를 이렇게 잡았다.

```css
  .ft-links-full > .ft-sep-outer {
    display: none;
  }
}          ← 이것을 `@layer components`의 닫는 괄호로 읽었다
```

실제로는 `@layer components`가 **2871줄에서 이미 닫혀 있었고**, 저 `}`는 3051줄에서 시작한
**`@media (max-width: 380px)`의 닫는 괄호**였다(design `14c` 「320px 접힘」 Footer 전용 —
그 자체는 정상 CSS다).

🔴 **이 함정은 소스에서 보이지 않는다.**

| 왜 안 보이나 |
| --- |
| 들여쓰기가 2칸으로 **맞아 보인다** — 미디어 쿼리 안도 `@layer` 안도 같은 깊이다 |
| `npm run build`가 **통과한다** — 문법이 유효하다 |
| `npm run lint`가 **통과한다** — CSS를 보지 않는다 |
| 번들에 선택자가 **존재한다** — `grep .set-head dist/*.css`는 1건을 찾는다 |

**진단 경로**: 사용자가 준 세 갈래(① 이름 불일치 ② `cn()`이 떨어뜨림 ③ 프리뷰가 옛 산출) 중
**어느 것도 아니었다.** 클래스는 DOM에 붙었고 CSS는 번들에 있었고 프리뷰는 최신이었다.
결정적 관측은 **「번들에서 `.set-head` 직전에 `@media`가 있는가」**였다.

🔴 **규약으로 승격한다** — CSS를 파일 끝에 추가한 뒤 **번들에서 새 선택자 직전에
`@media`·`@supports`·`@container`가 없는지 확인한다.** 소스 검토로는 잡히지 않는다.

⚠ 원인이 「Footer만 멀쩡했다」로 좁혀졌던 것도 기록해 둔다 — `.ft-*`는 `@layer` 안이었고
`.set-*`만 밖이었다. **한 파일 안에서 「어떤 것은 되고 어떤 것은 안 되는」 상태**가
미디어 쿼리 갇힘의 신호다.

### 4.4 🔬 `USER_WITHDRAW`는 발명이 아니라 **PRD 내부 어긋남의 보정**이다

🔬 **규칙 실측 — 지시서의 전제를 하나 정정한다.** 지시서 §2.3은 「없으면 만들지 마라 —

**`action`을 보지 않는다.** 막는 것은 규칙이 아니라 「스키마에 없는 값을 쓰게 된다」는 점이다.
**`B-18`이 이것을 잠근다** — 임의 문자열 `ZZ_NOT_IN_UNION`도 통과한다(통과기대).

🔴 **그래서 `firestore.rules` 재배포가 필요 없었다.** diff 0줄로 탈퇴 배치가 돈다.

**개인정보** — `before`/`after`에 이름·이메일을 담지 않았다. `admin.ts`의 `HEAD_TRANSFER`가
`{ headUid }`만 담은 규율(W-15A §4-9) 그대로다. 🔴 **이것이 §14.3 익명화(v1.2)와 양립하는

### 4.8 🔴 W-17F 보정 ① — `button` 행과 `div` 행의 기하가 갈렸다

**관측**: 알림 토글과 `버전` 값은 카드 우측 끝에 붙는데 **`설치 안내` 칩 · `›` 3종은 안쪽으로
들어와 있었다.** 구분선의 좌우 끝도 행마다 달랐다.

**원인**: `.set-row`가 `width:100%`인데(전역 `box-sizing:border-box`) `.set-row-tap`이

것인데, `border-box`에서는

```
width:100%      → 테두리 상자 = W
margin 0 -20px  → 상자가 −20 ~ W−20 에 놓인다        (구분선이 어긋난 이유)
padding 0 20px  → 콘텐츠 = 0 ~ W−40                  (우측 요소가 40px 안쪽인 이유)
```

`버전` 행만 멀쩡했던 것은 **그 행만 `div`**라 `.set-row-tap`이 없었기 때문이다.

**고침**: 🔴 **음수 마진·패딩을 걷어냈다.** 그리고 `button`의 UA 기본값(`padding`·`border`·
`font`·`color`·`text-align`)을 `.set-row`·`.set-acct`·`.set-logout`·`.set-withdraw`에서
**전부 초기화**해 `div` 행과 픽셀 단위로 같게 만들었다. 🔴 **여백을 더해 눈으로 맞추지 않았다** —
그 방법은 루트 32px(AC-05)이나 200% 확대에서 다시 어긋난다.

🔴 **눌림 하이라이트가 카드 콘텐츠 폭까지만 칠해지는 것은 부작용이 아니라 교정이다.**
design `20a`의 행은 카드의 `padding: 18px 20px` **안쪽**에 있다 — 카드 끝까지 번지던 이전
상태가 시안과 어긋난 쪽이었다. **시안과 일치하게 됐다.**
