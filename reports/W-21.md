**🔴 폴백 (DoD 7) — 글자가 사라지지 않는다**

두 위험을 각각 닫았다.

1. **`background-clip:text` 미지원** — `color:transparent`를 **맨몸으로 쓰지 않았다.**
   두 선언을 `@supports (background-clip: text) or (-webkit-background-clip: text)` 안에
   **함께** 가뒀다. 지원하지 않으면 W-20까지의 거동(상자가 반짝인다)이 그대로 남고 **글자는 언제나 보인다.**
   🔬 번들 확인: `@supports ((-webkit-background-clip:text) or (background-clip:text)){.shine{color:#0000;-webkit-background-clip:text;background-clip:text}}`
   — lightningcss가 접두사판을 **자동으로** 붙였다(손으로 적지 않았다 · W-02 §4-1 규율).
2. 🔴 **기저색이 투명이면 지원 환경에서 글자가 사라진다.** 기존 정지점은
   `rgba(255,255,255,0) → 0.45 → 0`이라 **띠 밖이 전부 투명**이었다. 기저를 `0.82`,
   띠를 `#fff`로 뒤집었다 — 흰 라벨의 광택은 「더 밝아지는 것」이 아니라
   **「기저가 조금 어둡고 띠가 순백인 것」**으로만 성립한다(흰색보다 밝은 색이 없다).
   🔬 대비 실측(`--gradient-primary`의 밝은 끝 `#2E6B4C` 기준): 기저 **4.80:1** · 띠 **6.24:1**.
   §15.2 AC-01(18px 미만 4.5:1)을 **양쪽 다 넘긴다.**

⚠ **실기기 확인이 남았다** — `background-clip:text` 지원은 기기마다 다르다(DoD 7 · §6.3).

### 4.2 🔴 결정적 관측

사용자가 standalone에서 본 한 바퀴:

```
앱 로그인 화면 → 앱을 벗어나 Safari → Google 로그인 완료 → 다시 앱 로그인 화면
```

**「앱을 벗어나 Safari로」**가 전부를 설명한다.

| | 값 |
| --- | --- |
| 앱 출처 · manifest `scope` | `https://sundo-dev-8ef38.web.app` · `/` |
| `authDomain` | `sundo-dev-8ef38.firebaseapp.com` — 🔴 **scope 밖 · 다른 출처** |

iOS standalone은 **manifest `scope` 밖 내비게이션을 Safari로 내보낸다.** `signInWithRedirect`가
`firebaseapp.com/__/auth/handler`로 가는 순간 앱을 벗어나고, OAuth가 **앱과 다른 브라우징
컨텍스트**에서 끝난다. `signInWithRedirect`가 심어 둔 대기 상태와 `getRedirectResult()`가
읽어야 할 저장소는 **standalone 앱 컨테이너**에 있는데 크리덴셜은 **Safari 컨테이너**에서
확정된다 → 앱으로 돌아와도 `getRedirectResult()`는 `null` → `signedOut` → S1 → 탭 → **반복.**

🔴 **브라우저 탭이 멀쩡한 이유가 같은 사실의 뒷면이다** — 탭은 `isStandalone() === false`라
`signInWithPopup`을 타고, 팝업은 같은 컨텍스트를 공유한다.
⇒ **`signInWithRedirect` 경로는 이 앱에서 한 번도 성립한 적이 없었다.**
`reports/W-19.md` §5-3이 미측정으로 남긴 바로 그 자리다.

⚠ **지시서가 경고한 시점 논증(「W-19에서는 됐는데 W-20에서 깨졌다」)을 쓰지 않았다.**

「캐시된 반 목록 표시」를 요구하지 인원 수 생략을 허용하지 않는다).

**왜 W-21에서 안 고치나** — 집계를 캐시 가능한 형태(`getDocs` 후 클라이언트 카운트)로
바꾸면 S3 진입마다 **학생 문서 1,033건**을 받게 된다. 읽기 비용·오프라인 캐시 크기·
`(오프라인)` 표기 신설이 한 덩어리로 딸려 오는 **설계 회차 규모**다.

### 결함 B — ⚠ 오프라인 S5 명부 (원인 미확정)

**관측** — 비행기 모드에서 앱을 새로 열고 홈 → 학년 → 반으로 들어가면
**`학생 명부를 불러오지 못했습니다`**(ER-03)가 떴다. 사용자가 뒤에 「착오였다」고 회신해
13·17번은 통과로 닫혔으나, **관측 자체는 취소되지 않았다.**

🔴 **두 사실이 서로 모순되어 원인을 확정하지 못했다.**

1. SDK 원문상 `getDocs`는 오프라인에서 **reject하지 않는다**
   (`r.fromCache && "server" === i.source ? reject : resolve`). ⇒ ER-03은 `fetchDepartment`의
   `getDoc`에서 와야 한다(`getDoc`은 캐시 미스 시 **reject**한다 — 원문 확인).
2. 그런데 `fetchDepartment`가 실패했다면 **S4에 반 버튼이 하나도 안 그려진다**
   (`classCount`가 0으로 떨어진다). 반을 눌러 S5에 도달했으므로 S4에서는 성공했고,
   결과가 모듈 `deptCache`에 남아 S5에서도 성공해야 한다.

⇒ **내가 모르는 경로가 하나 있다.** 가르려면 기기에 디버거를 붙여 실제 오류 코드를 봐야
하는데 🔴 **iPhone뿐이고 Mac이 없어 Safari Web Inspector를 붙일 수 없다.**

**W-21B 진단 절차** — ① Android + `chrome://inspect`, 또는 Mac + Safari 웹 인스펙터로
`roster.ts`의 `errorCode(...)` 실제 값을 본다 ② `unavailable`이면 `getDocs`의 리스너
`error` 경로이므로 SDK를 더 판다 ③ `firestore/department-failed`면 위 2번 추론이 틀린
것이므로 S4의 렌더 분기를 다시 본다.

⚠ **곁가지 하나 — 아직 관측되지 않았으나 코드에 있다.** `getDocs`가 오프라인에서
**빈 결과를 조용히 돌려주므로**, 캐시에 없는 반을 열면 **EM-01 「이 반에 등록된 학생이
없습니다」라는 거짓말**이 뜬다. `roster.ts`의 문서 주석이 정확히 그것을 경고하는데
**막는 코드가 없다**(`snapshot.metadata.fromCache`를 보지 않는다).
관측되지 않은 것을 고치지 않는 것이 이 회차의 규약이라 손대지 않았다 — **W-21B 항목**이다.
