W-02는 Chrome 확장으로 `getComputedStyle`을 읽었으나 이번 세션에서는 **확장이 연결돼 있지 않았다.**

## 4. 판단이 필요했던 지점

### 4-1. `.ff-ro`의 "테두리 없음"을 `border: 0`이 아니라 투명으로 바꿨다

DoD 15 실측에서 **읽기 전용 필드만 라벨 좌측 기준선이 다른 필드보다 1px 왼쪽**이었다
(border box 기준 16px vs 17px, `top`도 9px vs 10px).

원인은 `.ff-ro { border: 0 }`이다. `.ff`는 `box-sizing: border-box`이고 라벨은 `position: absolute`라
**포함 블록이 padding box**다. 테두리를 지우면 padding box가 사방 1px씩 커져 라벨이 함께 밀린다.

→ `border: 1px solid transparent`로 바꿨다. 시각적으로는 여전히 테두리가 없고(§7.3 상태 7 충족),
높이 56px·기준선 16px이 다른 상태와 완전히 같아진다. 재측정 결과 `borderTop: 1px rgba(0,0,0,0)`,
기준선 17px(border box) = 16px(padding box), `height: 56px`, `box-shadow: none`.

### 4-2. 성공 상태를 blur·제출 시점으로 제한했다 (사양 위반 수정)

재개 후 실측에서 **에러가 뜬 필드에 타이핑하는 도중 성공 체크가 즉시 나타났다.**
지시서 §5.5는 "성공 아이콘은 `validate`가 주어진 필드에서만, **blur 후 통과했을 때** 표시한다"이므로 위반이다.

원인은 `runValidate()`가 통과 시 무조건 `setOk(true)`를 했고, 이 함수를 값 변경 재검사 경로가
그대로 호출한 것이다(§5.5의 "에러가 뜬 필드는 값이 바뀔 때마다 즉시 재검사").

→ `runValidate(v, allowSuccess = false)`로 바꿨다.
- `onBlur` → `allowSuccess: true`
- `ref.validate()` → `allowSuccess: true`
- 값 변경 재검사 → `false` (에러 해제만, 체크 없음)

**`ref.validate()`를 `true`로 둔 근거**: §5.5는 성공을 "blur 후 통과"에 묶었지만 §5.6의
`ref.validate()`는 "제출 시 폼이 호출하는 전체 검증"이다. 금지하려는 것은 *타이핑 중* 성공 표시이지
검증 완료 시점의 표시가 아니다. 제출 검증만 성공 표시를 못 하게 하면 같은 통과 결과가
경로에 따라 다르게 보인다. **판단이 갈릴 수 있는 지점이라 §7에 확인 요청으로 남긴다.**

### 4-3. 포커스 1.5px 선을 `border-width`가 아니라 inset 그림자로 냈다

§7.3 상태 2는 "테두리 `1px` → `1.5px`"다. 실제로 `border-width`를 바꾸면 padding box가 0.5px 줄어
라벨과 값 텍스트가 포커스마다 미세하게 움직인다. `inset 0 0 0 1.5px`로 내면 두께는 같고 레이아웃은 고정이다.
DoD 15("부상 전후 기준선 동일")도 이 방식이라야 성립한다.

### 4-4. reduce에서 스피너는 정지시키지 않았다

AC-07은 장식 모션을 정지시키라는 요구다. 스피너는 "서버 확인 중"을 알리는 **유일한 피드백**이라
정지시키면 상태 전달 수단이 사라진다. 실패 상태에서 색·아이콘·문구를 남기라는 §5.7 주의와 같은 논리다.
실측에서 reduce 시 `spin`만 유지되고 오라·shake·라벨 전환·체크 드로잉·문구 펼침은 전부 정지한다.

### 4-5. 에러 문구 높이 `0→auto`를 `grid-template-rows`로 냈다

`height: auto`는 전환되지 않는다. `display: grid` + `grid-template-rows: 0fr → 1fr` + 자식 `overflow: hidden`이
0.2s 전환이 실제로 걸리는 방식이다. 문구 노드는 **항상 마운트**한다 — `role="alert"` 라이브 영역이
에러보다 먼저 존재해야 스크린 리더가 낭독한다.

### 4-6. 오라 좌하단은 `aur1`을 재사용했다

`design/index.html`에는 `@keyframes aur1`·`aur2` 2개뿐이고 블롭은 3개다. 좌하단에 `aur1`을 12s로 걸었다.
8s와 12s는 주기가 달라 좌상단과 동기화되지 않는다. 새 키프레임을 지어내지 않았다.

## 7. 사용자 확인이 필요한 사항

1. **`ref.validate()`가 성공 체크를 띄우는 것이 맞는가** (§4-2). 지금은 띄운다.
   - 되돌리기 비용: `Field.tsx` 한 줄(`runValidate(value, true)` → `runValidate(value)`).
   - 다만 지금 구조에서 이걸 끄면 **스토리 페이지에서 상태 4를 렌더할 방법이 없다**(blur를 프로그램으로 못 만든다).
     끄기로 하면 성공 상태 검증 방식을 함께 정해야 한다.
2. **`.ff-ro` 테두리를 투명으로 바꾼 것**(§4-1). PRD §7.3 상태 7 문구는 "테두리 없음"이다.
   투명 테두리는 시각적으로 동일하되 기준선이 맞는다. 문구 그대로 `border: 0`을 원하면
   읽기 전용만 라벨이 1px 어긋나는 것을 받아들여야 한다.
3. **`--color-sundo-tint-06` 신설 여부**(§6). 읽기 전용 배경이 2회 쓰이고 W-03B의 비활성 상태에서
   더 나올 가능성이 있다. PRD §7.1 수정이 필요해 PM 판단 사항이다.
4. **`inset 0 1px 3px rgba(20,53,38,0.05)` 토큰화 여부**(§6). 이미 5회 반복이다.
   W-02 §5.3이 정한 "같은 값이 또 인라인으로 나오면 토큰화 후보" 기준에 걸린다.
5. **스피너를 reduce에서 정지시키지 않은 것**(§4-4).

## 8. W-03B에 넘기는 전제

- `cn()`은 이제 커스텀 글꼴 크기 13종·반경 12종·그림자 3종을 안다. **문자열 결합 우회를 쓰지 마라.**
  새 커스텀 스케일을 `@theme`에 추가하면 `src/lib/cn.ts`의 `classGroups`에도 함께 등록해야 한다.
- `AppShell`의 API는 `hasDock`·`bottomGap` 2개뿐이다. Dock 자체는 W-03B다.
  `hasDock`이 켜지면 상단 34px·하단 120px이 이미 잡히므로 **Dock 컴포넌트가 여백을 또 만들지 마라.**
- 오라 블롭은 스테이지에 고정돼 있고 스크롤 영역 바깥이다. GlassCard 등에서 배경 장식을 또 깔 필요가 없다.
- `rise`(카드 등장) 모션과 `.pill-fill` 그림자 문제는 W-03B 몫이다.
  `.pill-fill` 그림자 없음은 **의도된 차이로 확정**됐다(지시서 §0.3-2). 실제 목록 행에 렌더한 뒤 재검토한다.
- 모든 텍스트 입력은 `Field`만 쓴다. 글자 수 카운터(R-07)·`scrollIntoView` 보정(AC-12)은 W-09다.
- `Switch`에 터치 타깃 44px 보정은 아직 없다(W-18).
- 검증 러너는 여전히 없다. W-08에서 vitest를 도입할 때 이 보고서의 실측 항목이 그대로 테스트 후보가 된다.
